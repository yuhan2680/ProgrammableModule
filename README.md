# 可编程模块 · 编程练习

独立应用图标已配置到 macOS 和 Windows 导出预设。图标文件、正式发布导出方式及 `DEBUG` 标题说明见 [应用图标与正式导出](docs/EXPORTING.md)。

Godot 4.5+ / GDScript 工程。按 **F5** 进入主菜单，提供「开始游戏」「地图编辑器」「设置」「离开游戏」。内置第一至第十五关，共 15 个教学关卡。点击「开始游戏」后，关卡页分为「教学关卡」与「导入关卡」。教学默认显示前七关，右侧「展示更多（15）」展开全部，支持收起；数字随教学总数更新。导入入口与用户关卡独立成组，两个分类都按每排七项显示、上下滚动。刷新或游玩返回会保留本次会话的展开状态。界面采用浅灰背景、白色圆角卡片和蓝色主要操作，支持简体中文、繁體中文和 English 切换，语言选项固定按此顺序排列。主菜单卡片左上方并排显示小图标与标题，右侧放置「开始游戏」和「地图编辑器」，「离开游戏」与「设置」分别位于左下角和右下角。底部按钮与卡片边缘保持 16 像素等距内缩，16 像素按钮圆角与 32 像素卡片圆角同心。选关图标使用根据地图自动生成的 SVG 缩略图，显示路线、起终点与机关；导入关卡也会自动生成，刷新后跟随地图更新。 入口图标缩小为104像素，外框采用34像素圆角，内部SVG白底同步增大圆角；名称与完成状态保持独立换行，七列在中英文和最小窗口下均可完整显示。

游戏启动时先显示白底、黑色细圆头进度条，按实际资源加载和初始化阶段推进；背景缓存完成后进度满格，先显现模糊背景，再弹出白色菜单窗口。加载失败可重试；不会为展示进度条额外等待。引擎脚本运行前使用同样的静态空轨道衔接。

开始页面默认使用随项目打包的图片背景，等比例居中铺满窗口并应用约 64 像素高斯模糊；中央菜单卡片、插图和文字保持清晰。「设置 → 颜色与显示」可选择默认图片、原有浅灰纯色或导入自定义图片。自定义背景沿用相同模糊强度并独立保存副本；新增图片接在默认、纯色和自定义入口右侧，始终保持同一排；超出可见范围后通过常显的横向滚动条浏览，未使用的自定义背景可右键删除。其他页面继续使用原有浅色背景。

选关页顶部采用紧凑导航栏，左侧箭头返回开始页面。右侧搜索图标向左缓动展开搜索框，按当前语言显示的关卡名称实时匹配，包含教学与导入关卡；折叠中的关卡也可直接搜索。点击双箭头或按 Esc 收起并清空搜索，恢复原来的教学展开状态。刷新及游玩返回保留当前搜索；切换语言后按新语言名称重新匹配。

右上角圆形「…」展开半透明圆角菜单，提供带 SVG 图标的「刷新」「导入关卡」和「排列方式」子菜单。排列方式提供「默认顺序」（按关卡序号）与「未通关优先」，当前选项显示勾选标记。未通关优先在各自分组内稳定排列，同状态仍按关卡顺序显示，下方导入入口始终排在第一格。排序状态在当前会话的刷新与关卡往返间保留。点击空白处、再次点击「…」或按 Esc 可关闭；也支持键盘选择。刷新保留搜索和教学展开状态，导入复用原有文件夹与取消流程。

地图编辑器顶部与选关、组装和编程页共用同尺寸、同位置的返回药丸。右侧为「新建 / 保存」「撤销 / 重做 / 更多」胶囊和独立「重载内容」按钮，使用高清 SVG 与玻璃悬停名称。「更多」下拉提供「另存为、校验、元数据 JSON」；点击地图路径或按 Ctrl/Cmd+O 打开地图，仍保护未保存修改。试玩返回保留同一文档与历史。

地图有未保存修改时，返回开始页会显示带黄色 SVG 警告图标的毛玻璃确认窗口，提示中显示当前地图名称，长名称自动换行。纵向的「保存」「不保存」「取消」分别用于保存成功后返回、放弃修改并返回、继续编辑；首次保存可选择文件位置，保存失败或取消文件选择都会留在编辑器。

游戏地图与地图编辑器的空白区域使用低对比度的浅蓝灰石材纹理，保留细网格；两套纹理均已重绘并提高铺设密度，编辑器放大时仍保留细节。通行地板使用明亮、低对比度的细划痕纹理，保留清晰的圆角边框，与周围石纹形成明暗区别；模块仍清晰显示。空白区域的不可通行规则不变。

地图编辑器中的地图默认居中，小地图保留原始比例，大地图自动完整适配。卡片右上角的「− / +」或滚轮可缩放，放大后超出画幅的部分可通过滚动条查看；缩放与视点只影响显示，不进入地图撤销历史，试玩返回后保留。原地形提示、编辑状态和目录说明移入「？」玻璃指引浮窗，错误仍通过原有错误弹窗反馈。右侧地图属性改为标签与输入框同行的紧凑表单，宽高并排；滚动条与输入区留有独立间隔，只在滚动时显示，停止后淡出。

地图属性中的「画笔样式」提供 SVG 画笔与框选按钮，「绘制项目」选择地块或擦除。画笔保持连续拖动绘制；框选显示淡色透明虚线范围，松开后填充整个区域，整块修改可一次撤销或重做。Esc、切换工具或缩放会取消未提交的选区。右键可框选擦除。「场景玩法与行为控制」提供独立 SVG 起点与终点按钮，选择后单击可通行地块放置，拖动不会重复移动；右键或 Esc 返回地形绘制。「重置起点 / 重置终点」使用 `#dd1d1d` 红字，可分别清除并支持撤销。终点为可选项：不添加也可保存和自由测试，添加后按该位置判定通关。

「场景编辑」和「场景玩法与行为控制」标题旁的 SVG 箭头可分别收起或展开该分类，默认展开；场景编辑包含宽高、画笔样式和绘制项目；场景玩法与行为控制包含起终点、限时、两项玩家上限和敌人设置。折叠保留输入值和点位，试玩返回也保留折叠状态。

「场景玩法与行为控制」中的秒表药丸可直接输入时间限制，单位为秒，默认 **60 秒**，须大于 0 且不超过 **3600 秒**；不支持空白或 0 作为不限时。按回车、失焦、保存或开始测试时提交，无效内容恢复有效值；限时跟随地图保存并支持撤销重做。运行程序才开始倒计时，暂停冻结，重试恢复；在截止时刻之前或恰好截止时到达终点、或摧毁所有敌人的全部模块即可通关，两个条件满足任一个即可。待生波次也必须清除；原本没有敌人不会自动获胜。没有终点和敌人也可进行限时测试，到时失败；主程序提前结束仍继续计时。

「场景编辑」将宽、高和「应用尺寸」集中在一行，英文使用 W / H。输入仅接受 `1..64` 的整数，键入、粘贴与应用入口均校验；载入旧大地图仍如实显示原尺寸，不自动裁剪。绘制项目中的显示名称随界面语言切换（例如「地板」/「Floor」），括号中的地块 ID 和当前选择保持不变。

「玩家模块数量上限」和「玩家耐久度上限」并排位于玩法分类中。耐久默认显示 **1**，支持正小数，设置后应用于本地图内玩家每个模块的初始和最大耐久；敌人耐久不受影响。该值随地图保存并支持撤销、重做和未保存试玩，重新运行恢复完整耐久。旧地图未设置此项时继续继承各模块定义中的耐久。

装配页使用横向 SVG 蓝图。左侧毛玻璃「＋」按钮从原位置向右下展开模块目录，左上角返回钮收回；默认只显示图标与名称，目录右上角说明按钮统一展开或隐藏各模块功能。目录高度保持一致，隐藏说明时下方留白。选择模块后侧栏收回，左键在图纸上放置、选择或拖动模块。「设置 → 显示」在「Tab 补全」下方提供「装配图尺寸自由缩放」，默认关闭：完整显示固定的横向蓝图与白框，不启用滚轮缩放、右键拖图或边缘淡出。开启后，滚轮围绕光标缩放，右键拖动图纸，越过画幅的边缘渐隐。上缘使用与设置页相同的 48 像素透明过渡，图纸、模块和选中框合成后一起淡出，格线保持清晰。关闭时恢复完整图纸，并保留模块与相对坐标。开关即时生效并独立保存；准备页、工作台装配页签和地图编辑器试玩共用同一偏好。Del（macOS 也支持 Delete/Backspace）或「＋」下方圆形删除按钮移除选中模块。缩放、平移和目录开合只改变显示，不写入装配草稿；首个模块的落点确定视觉原点，后续偏移相对该点计算；格子仍为 0.5，偏移范围仍为 -4..4，中心和沿边连通校验保持原规则。

## 代码区配色

在「设置 → 显示 → 颜色与显示」中点击浅色或深色代码预览，选择会立即保存，下次进入游戏继续使用。默认浅色；深色编辑区采用 `#121314` 背景，并适配语法高亮、行号和补全灰字。详细行为见 [代码区颜色与显示](docs/CODE_COLORS.md)。

## 开始游戏

1. 使用 Godot 导入根目录 `project.godot`，等待资源导入后按 **F5**。
2. 在主菜单点击「开始游戏」，选择「第一关 · 初次移动」。
3. 每次进入关卡先打开独立组装页，装配为空。点击左侧「＋」选择移动模块，在图纸内任意落格，该位置即成为装配原点 `(0,0)`；确认装配后进入编程页。
4. 点击「运行程序」，或在代码编辑器按 **Ctrl+Enter**。运行时高亮当前行，可暂停、继续、停止或重置位置。
5. 让机器沿 S 形地板抵达绿色终点即可通关。程序提前结束、语法错误或遇到 void 都会显示明确提示。
6. 草稿和通关记录按关卡保留，源程序会自动恢复。再次进入仍从空装配开始；需要沿用上次布局时，主动点击「载入上次装配」。

要重新从示例开始，打开编程页右上角「更多」菜单并点击红色「重置代码」：停止当前运行并恢复本关初始程序，保留装配与通关记录。恢复后的程序会更新当前关卡草稿；误点时可在程序编辑区撤销。地图编辑器试玩同样支持恢复初始程序，但仍只保留在当前测试会话内。

关卡组装与编程页面隐藏顶部软件图标，使用与选关页同尺寸、同位置的药丸形箭头导航。组装页保留简短说明；编程页关卡名称移至卡片外的顶部栏，下方以小字显示目标。返回操作继续保留原有草稿保存与编辑器试玩流程。

关卡引导支持左侧「上一页」与右侧「下一页」；第一页禁用返回，末页点击「开始编辑」结束。装配页可通过顶部「关于说明」，编程页可通过「更多 → 关卡说明」重新打开。

编程页的导航与操作集中在同一顶部栏：左侧为药丸返回和关卡说明文字；右侧依次为蓝色运行、暂停/继续、停止、重置位置、更多，以及独立的指令集合书本按钮。所有图标使用 SVG，并提供本土化悬停名称。更多菜单以半透明面板下拉，提供关卡说明、编辑模块、重置位置、红色重置代码和保存草稿；地图编辑器试玩隐藏保存草稿。运行锁、暂停进度、代码撤销和自动保存仍沿用原有流程。

编程页顶部栏显示当前关卡名称及简短目标，文字与留白区域不触发悬停提示。所有悬停提示的文字、内边距、圆角与阴影统一缩小至原来的70%，二级菜单保持原尺寸。按钮等交互控件的悬停提示采用实时背景模糊、浅白玻璃底、亮边和柔和阴影，深色文字保持清晰，不使用深色描边；出现时机、禁用原因及关闭行为仍由原生提示管理。地图卡片右上角的 SVG 问号悬停显示「指引」，点击打开毛玻璃小窗，集中显示目标、行动指导、机关或敌人状态、角度方向与地形说明。点击外部、再次点击问号或按 Esc 关闭；阅读不会暂停模拟，动态状态仍跟随同一会话更新。运行时，问号正左侧的渐变长药丸从右向左缓动展开，动画中靠近问号的一端更淡、左侧更明显，完整展开后保持均匀的半透明毛玻璃底，使用原分辨率局部采样和轻微柔化透出下方地图，文字独立清晰绘制，显示倒计时与敌人状态，暂停保留数值，结束后短暂停留再收回。倒计时数字使用 `#d82929` 并加粗。

编程工作台的地图右上角提供「全尺寸预览」SVG 按钮：先从左到右淡出代码卡片，再展开地图卡片；展开后按钮提示「缩小至小尺寸」，再次点击先缩回地图再恢复代码区。顶部标题和操作栏始终保留，过渡期间锁住操作，完成后恢复当前运行状态；倒计时药丸始终位于问号左侧。代码、装配、选择和原分栏位置保留，地图按完整宽高比重新适配可用画幅。全尺寸下通关或失败时，同一药丸会替换倒计时、敌人等状态，显示本次结果并保持展开；退出全尺寸、重置位置或停止运行后清除。结果按当前语言显示，长消息可悬停查看完整内容。

近战攻击轨迹以 `#951616` 的扩散光束呈现：从发射模块处较窄地射出，向末端逐渐变宽，边缘带柔和光晕，暗相与射程末端仍清晰可见。显示端点跟随当帧移动后的发射模块和实际受击模块，避免命中时出现视觉空隙；如果击毁部件后下一 tick 才因该部件不可用而失败，终止画面保留刚才击毁部件的接触光效，避免被后续落空光束覆盖；正常运行仍显示当帧攻击。原始射线和伤害判定不变。光束前端越接近存活的玩家模块，亮暗闪烁越快；暂停会冻结闪烁，重新运行重置显示相位。

编程工作区的地图与编辑卡片上下对齐，并向窗口边缘扩展。右侧卡片内使用扳手 / 拼图 SVG 药丸切换组装与程序，悬停分别显示「组装」「程序」。切换保留草稿及原有运行限制；空闲时收起底部常驻提示，运行结果、错误及手动保存反馈继续显示。

在编程页打开右上角「更多」菜单并点击「编辑模块」，可直接返回组装页面，保留当前程序与装配，无需重开关卡。运行或暂停期间点击会先停止本次试运行；修改后点击「确认装配，返回编程」继续编辑程序。

第一关仍只允许 **1 个移动模块**，没有预装模块。第一个模块可放在图纸内任意格点，其落点成为装配原点 `(0,0)`；只有一个模块时不能移离该原点，但可以重命名或移除。删除全部模块后可重新选择原点。左侧列表显示所有已注册模块，未解锁项不可选择，达到数量上限后禁用新增。

允许多个模块的自定义关卡中，后续新增或移动的模块必须与任意已有模块的实际矩形边缘共边，接触长度必须大于零；允许分支，角点接触或留有空隙都不算连接。偏移仍使用半格网格，范围 `-4..4`，模块不能重叠。

删除中心模块或连接两部分的模块后，可以保存并手动恢复不完整草稿继续修复。确认和运行要求非空装配、中心有模块、全部模块沿边连通，且完整出生占地位于可通行地形上。未满足时确认按钮禁用，悬停可查看原因；能保存草稿不代表能运行。

设置中的「显示 → Tab 补全」默认开启，并独立保存偏好。编写代码时，输入指令前缀（例如 `mo`）会显示淡灰色的 `ve`，按 Tab 接受，Esc 收起；没有建议时 Tab 仍用于缩进。建议仅使用本关已解锁的语法与当前装配的具名能力，不填写参数或关卡答案。自动配对括号内也支持提示，灰字不会覆盖右括号。关闭开关、选中文字、使用多光标、输入法正在组词或运行锁定时不显示补全；建议在接受前不会进入代码或草稿，接受后可以撤销。

第三关建议中心安装移动模块，右侧 `(0.5,0)` 安装近战模块，执行：

```text
    attack(0)
}
```

## 第四关：远程打击

在中心安装一个射击模块。敌人从右侧 **6 格**处向左移动 **4.5 格**，然后向左近战攻击。敌方模块独立受伤与失效；打掉前方移动模块并不算通关，需要存活并摧毁两个模块。

```text
main() {
}

tick() {
    shoot(0)
}
```

`main()` 执行一次，第四关新增的 `tick()` 每个逻辑 tick（0.1 秒）调用一次。射击模块冷却中重复调用不会发射，也不会报错。子弹逐渐减速，伤害与命中时的速度成正比，速度降为零后消失；每颗子弹只命中第一个目标。

`tick()` 本阶段只支持短动作 `shoot` / `attack`，不接受移动、循环或任意代码。前三关没有解锁 `tick()` 或射击。主程序结束后，第四关的敌人和已发射子弹仍会继续行动；暂停冻结整个模拟。为避免仅击坏移动模块后僵持，本关在 **15 秒**后结束未完成的练习，重试恢复双方耐久、子弹和冷却，并保留代码与装配。

第四关 JSON、战斗结算与扩展接口见 [射击与敌人设计](docs/SHOOTING_AND_ENEMIES.md)。

## 第五关：越狱行动

最多安装三个模块。先在中心放移动模块并命名为 `drive`，再在左右偏移 `(-0.5, 0)`、`(0.5, 0)` 放近战模块，命名为 `left`、`right`。选择模块后修改名称并点击「应用名称与位置」。首次进入仍需手动组装。

```text
main() {
    left.attack(180)
    right.attack(0)
    move(90, 5)
}
```

警卫位于出生点左侧 2 格，警报器在右侧 2 格。警报器先毁而警卫仍存活会立即失败；两者清除后安全门打开，还需向上到达绿色终点。按原设计备注，同一 tick 击毁两个目标也合法。

`模块名.attack()` 只调用对应实例，名称区分大小写；`模块名.move()` 和 `模块名.shoot()` 同样可用。命名移动只使用选中驱动的速度，整台机器共同移动；无名称的调用继续广播给同类模块。前四关默认不开放命名语法。详见 [越狱与命名调用](docs/PRISON_AND_NAMED_CALLS.md)。


## 第六关：循环阶梯

在中心安装 **1 个移动模块**。路线由十组「右 3、上 2」的阶梯组成，使用循环复用同一段指令：

```text
main() {
    loop {
        move(0, 3)
        move(90, 2)
    }
}
```

`loop {}` 是无限循环，不写括号或次数。块内每次移动完成后才执行下一条，块末返回块首；关卡检测到绿色终点后停止程序。暂停保留正在执行的移动与循环位置，停止或重试从起点重新开始，代码和装配保留。空循环会报错，零距离移动仍消耗逻辑 tick，不能导致界面卡死。

第六关通过 `allow_loops: true` 解锁循环；前五关默认不开放。`tick()` 内仍不允许循环，之前的命名调用能力继续可用。长阶梯自动缩放到观察区域，小网格下用蓝色标记辅助定位机器人。语法与调度细节见 [循环与阶梯](docs/LOOPS_AND_STAIRCASE.md)。

## 第七关：射击与躲避

上限两个模块，在一格宽的水平通道中对抗右侧6格处持续推进、持续近战的敌人。建议组合移动与射击模块，在 `loop` 中使用 `if (gun.ready()) { ... } else { ... }`：枪已就绪时射击，冷却时向后移动。`gun` 是玩家给射击模块取的名称。

`ready()` 只查询下一动作 tick 的冷却状态，不开火、不消耗时间；两个分支都需要填写动作。初始程序只提供空循环，由玩家自己完成条件和动作。每次移动完成后才重新判断，短步长便于及时射击；目标是存活并击毁敌人的所有模块，练习上限30秒。原有暂停、草稿、重置代码与空装配流程继续生效。

第七关通过 `allow_conditionals: true` 开放条件语法，前六关保持关闭。只实现本关所需的具名射击就绪条件，不开放通用变量或表达式。运行与扩展格式见 [条件判断与追击](docs/CONDITIONALS_AND_PURSUIT.md)。

## 第八关：左右为“铃”

最多安装三个模块。两个联动警报分别位于出生点左侧 **2 格**、右侧 **3 格**；只摧毁一个会触发另一个，全部解除前移动也会立即失败。先在同一个逻辑 tick 摧毁两只警报，再通过上方并排的两扇一格安全门到达绿色终点；两扇门会同时解锁。

本关新增 `simultaneously {}`：块内动作同时启动，全部完成后才执行后续代码。建议在中心放近战 `left`，向右依次共边放移动 `drive`（偏移0.5格）和近战 `right`（偏移1格）；中心不必是移动模块，这样两个近战模块都能从自己的位置够到目标。

```text
main() {
    simultaneously {
        left.attack(180)
        right.attack(0)
    }
    move(90, 6)
}
```

此参考解法仅写在文档中，游戏初始程序仍是空 `main()` 框架。并发块至少包含两条直接动作，不允许同一模块承担两条动作、同一机器同时移动两次，或在块内嵌套循环、条件和并发；也不能把它写在 `tick()` 内。所有攻击仍按同 tick 统一伤害结算，射程、碰撞、暂停与草稿规则保持一致。指令集合从新 JSON 自动读取说明，前七关不解锁新语法。详细规则见 [同时执行与联动警报](docs/SIMULTANEOUS_AND_ALARMS.md)。

## 第一关程序语法

```text
main() {
    // 先向右移动四格，再补充后续路线。
    move(0, 4)
}
```

- 每行一条指令，不使用分号；支持空行、`//` 注释和正负小数。
- `move(角度, 距离)` 完成后才执行下一条指令；受阻时停止并指向失败行。
- `0° / 90° / 180° / 270°` 分别表示右、上、左、下。距离单位是格，不能为负。
- 默认模块占地 `0.5 × 0.5` 格，速度 `1 格/秒`，底层每秒 `10` 个逻辑 tick。
- 未指定地块及地图外始终是 void。碰撞检查每个模块的真实占地和完整移动路径。
- 本关只开放 `main()` 与 `move`。循环、并行、变量、命名模块调用等后续能力会给出未解锁提示。

解释器已经使用独立 Lexer、Parser、显式 AST 和执行器，不执行 GDScript、Kotlin 或任意系统代码。

## 导入关卡

「敌人攻击方式与行为控制」可启用或关闭本地图的敌人；关闭保留已放置敌人和组合配置，试玩时不生成敌人。每组敌人的模块数量限制为 **1..256**，每个模块的耐久为 **0.01..1000000**。组合按所选模块顺序横向共边排列；修改模板只影响之后放置的敌人，已放置敌人保留各自配置。

同一次测试中，在组装与编程之间切换、停止或重置位置，都会保留当前程序与装配。点击顶部「← 地图编辑器」结束该次测试，恢复原编辑文档、文件路径、未保存标记和撤销/重做历史；下次开始测试建立全新会话。

编辑器测试的程序、装配和完成状态只保留在本次会话内，不载入或覆盖 `user://solutions/` 中同 ID 关卡的正式草稿和通关记录；测试界面不提供保存草稿或载入上次装配。

关卡列表只扫描内置 `data/levels/` 和用户 `user://levels/`。`data/maps/movement_lab.json` 是编辑器样例，不加入选关列表；十三个内置关卡位于 `data/levels/level_001.json` 至 `level_013.json`，第十关为雷达追猎地图，第十二关为八方向驻守地图。地图与关卡目录仍保持原有职责。

## 第九关：蜿蜒穿行

新增半格大小的测距模块，搭配移动模块穿过五段横向通道组成的长蛇形隧道。建议将测距模块放在中心，移动模块共边放在下方 `(0, 0.5)`。默认保持空装配和空 `main()` 框架，首次进入有七页教学说明。

`distance(角度)` 从测距模块中心测量前方首个阻挡表面的距离，不移动、不耗时；自身模块不遮挡测量。`sensor.distance(角度)` 指定命名的测距模块。可把读数减去安全间隙后交给 `move`，例如 `move(0, distance(0) - 0.5)`，再用 `loop` 重复右、上、左、上的转弯规律。查询会在每次执行时重新读取位置，不能把读数直接当成整台机器的安全行程。

关卡通过 `allow_distance: true` 单独解锁测距、有限数值加减及比较，前八关默认关闭；本关不引入变量。中英教学、模块 SVG、指令资料与搜索随 JSON 内容一起加载。测量规则见 [测距实现](docs/RANGEFINDING.md)，地图与教学见 [蜿蜒穿行](docs/RANGEFINDING_TUTORIAL.md)。

## 第十关：猎人游戏

最多安装三个模块，推荐中心雷达、右侧射击、下方移动。18×14 地图提供 16×12 的开放场地；单个敌人拥有 18 点耐久，以 0.75 格/秒随机游走，每 0.8–2.2 秒随机换向，碰到边界或障碍也会重新转向。练习限时 120 秒，击毁敌人完成。

复习循环、判空、冷却与短步追击；开放 `value` / `constant` 和 `variable`，但不要求使用。保留空装配和空 `main()`，指引说明快照刷新与弹道延迟，逐步代码提示提供不使用绑定的参考方案。每次重试使用新轨迹，暂停冻结同一模拟时钟。规则和回归见 [猎人游戏](docs/RADAR_PURSUIT.md)。

### 可选随机函数

第十关开始开放 `random()` 和 `randomInt(a, b)`，第十一至十五关也可直接使用。它们不需要额外模块，是否使用不影响通关判定：

- `random()` 返回 `0` 到 `1` 之间的随机小数，包含两个端点。
- `randomInt(a, b)` 返回 `a` 到 `b` 之间的随机整数，包含两个端点；两端必须是有限整数且 `a <= b`。

例如 `shoot(randomInt(0, 359))` 随机选择射击角度；`move(randomInt(0, 359), random())` 随机选择移动角度与距离。这些仅展示语法，随机移动仍可能撞墙或进入 void，并非关卡参考解法。每次执行调用都会重新取值；写入常量后保留该值，变量需要重新赋值才会刷新。详细范围、权限和运行规则见 [随机函数](docs/RANDOM_FUNCTIONS.md)。

## 第十一关：巧能躲避

本关最多安装两个模块，用 `function 名称() { ... }` 封装测距判断与闪避，再在 `main()` 中反复调用。敌人的移动、近战和雷达部件都参与真实模拟：每轮只锁定一次玩家位置，移到准备点后接近至前方一格，随后立即攻击。及时侧移，让五次实际攻击落空即可完成；任意玩家部件被该敌人命中都会立即失败。

保持空装配入口，初始源码仅提供空 `main()` 与函数框架，填写动作后再运行。第十一关继承第十关的玩家雷达、`scan()`、常量、变量、赋值与随机函数，仍可直接选择，不以第十关通关记录锁定。前九关保持原权限，模块上限仍为两个。可选中心测距或中心雷达配右侧移动模块，代码提示会按实际装配选择对应方案。

`variable target = scan()` 保存最近可见敌人的当次快照。先用 `if (target != null)` 判断，再读取 `target.Angle()`、`target.Position.x` / `.y` 或 `target.Distance`；`Null` 和 `Distance()` 也兼容。雷达扫描不消耗 tick，旧快照不会随敌人移动而自动更新。函数语法见 [函数复用](docs/FUNCTIONS.md)，绑定与作用域见 [常量与变量](docs/VARIABLES.md)，扫描几何及语法见 [玩家雷达](docs/PLAYER_RADAR.md)，场地与敌人节奏见 [巧能躲避](docs/FUNCTIONS_AND_DODGING.md)。


## 第十二关：八方来敌

最多安装两个模块，推荐中心测距模块命名 `sensor`，右侧 `(0.5,0)` 安装射击模块命名 `gun`。推荐留在场地中央，依次面对来自八个方向的八波敌人；每波仅一台，击毁其全部真实模块后才进入短暂等待并出现下一波。完成全部八波才通关。装配上限为两个，并继承此前全部五种模块；测距与射击是推荐方案，不额外取消已解锁能力。

本关以独立 `allow_for: true` 开放 `for (angle in 0..315 step 45) { ... }`，依次得到 0、45、90、135、180、225、270、315 八个角度。循环负责测距并记录发现敌人的方向，再在循环外射击；外层 `loop` 持续刷新扫描。`if` 可省略 `else`，不满足条件时继续后续语句。旧关卡不会自动开放 `for`。装配、有限循环、波次状态和模拟边界见 [八方来敌](docs/EIGHT_DIRECTIONS.md)。

## 第十三关：十面埋伏

最多安装两个模块，推荐中心 `(0,0)` 雷达和右侧 `(0.5,0)` 射击。十波敌人随机从任意角度依次接近，移动与近战模块分别具有 2.0 耐久。用 `scan()` 查询目标，先判断非 `null` 再读取 `Angle()`，循环扫描并射击。全部十波真实击毁才通关，波次间隔不会误判为胜利。

被击毁整机的残骸约 3 秒淡出；暂停冻结，终局继续收尾，重置恢复所有敌人与新的来袭角度。关卡限时 180 秒，保留已有指令权限与教学提示。详细规则及验证见 [十面埋伏](docs/AMBUSH.md)。

## 第十四关：通道清剿

使用移动、雷达和射击三个模块，沿四格宽主通道向上推进。左右各有五条细支道，铁栅栏阻挡机器但放行子弹、近战和雷达；墙壁会挡住攻击与扫描。发现敌人时持续瞄准射击，没有目标时短步前进，击毁全部十波通关。敌方每个移动/近战模块耐久 2.7，整机残骸约三秒淡出。地图、参考装配和兼容边界见 [通道清剿](docs/CORRIDOR_SWEEP.md)。


## 第十五关：自动索敌

最多安装三个模块，推荐雷达、射击和移动；沿用第十四关的四格宽主通道、左右各五条细支道与铁栅栏。240 秒内击毁全部十波敌人，每个敌方移动/近战模块耐久 2.8，整机残骸约三秒淡出。仍从空装配和空 `main()` 开始，由玩家确认装配后编程。

本关新增顶层 `radar.onDetected { EnemyPosition -> target }`。先声明全局 `variable target = null`，并将 `radar` 替换为实际雷达实例名。事件每个逻辑 tick 自动把最新目标快照写入该全局变量，无目标时写入 `null`；`main()` 判空后读取 `Angle()`、`Position.x/y` 或 `Distance`，无需循环调用 `scan()`。事件体仅接受这一条绑定。独立权限 `allow_radar_events` 在前十四关保持关闭；规则、参考程序和实现边界见 [雷达事件与自动索敌](docs/RADAR_EVENTS.md)。
