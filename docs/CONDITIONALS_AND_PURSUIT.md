# 第七关：条件判断与追击

依据 [ProgramLevel.md](https://github.com/yuhan2680/ProgrammableModule/blob/main/ProgramLevel.md) 第七关：最多两个模块、横向通道、敌人位于右侧6格并持续向左移动和攻击；射击冷却结束则开火，否则后退。文档没有指定冷却查询写法，本轮使用具名 `gun.ready()`，沿用第五关的模块命名方式。

## 地图与教学

`data/levels/level_007.json` 使用地图版本1，23×5，地板为 `(1..21,2)`，通道宽一格。玩家中心 `(14.5,2.5)`，敌人中心 `(20.5,2.5)`。玩家上限2，保留移动、近战、射击等既有模块解锁。每次进入先空装配，模板仅作定义与校验参考，不自动替玩家安装。

敌人为 `advance_attack`，前方近战实例偏移 `(-0.5,0)`、耐久10，后方驱动偏移 `(0,0)`、耐久1，速度使用原移动模块。高耐久使站着开火无法在接敌前结束战斗，左侧地板为退让提供空间。目标仍是存活并击毁全部敌方模块，最长300tick（30秒），不通过匹配玩家源代码判断胜利。

初始编辑器只提供空的 main / loop 框架；引导解释查询、分支、步长和观察反馈，不预填方向、移动距离或完整解法。参考程序仅用于维护者复验，不载入玩家编辑器：

```text
main() {
    loop {
        if (gun.ready()) {
            gun.shoot(0)
        } else {
            move(180, 0.1)
        }
    }
}
```

参考装配：`drive` 在 `(0,0)`，`gun` 在 `(0.5,0)`。实际模拟中0.1后退步长96tick通关，0.2与0.5步长105tick通关，1格步长113tick通关。原地单枪与双枪均失败，只后退会触碰左侧void。参考数值记录当前版本，不作为关卡硬编码限制。

## 2026-09-17：可省略 else 的兼容扩展

已解锁 `allow_conditionals` 的关卡现在也接受 `if (条件) { ... }`。条件为假时直接继续下一条语句，不需要书写无意义的占位 `else`，也不增加模拟 tick；原有 `if / else` 写法保持有效。`if` 主体和显式书写的 `else` 仍必须非空，省略的 `else` 在 AST 中表示为有效空块。省略后下一条语句仍须另起一行。该扩展不附带开启 for、变量或任何查询权限。

进入时仍检查所有分支与能力；连续无动作执行受 4096 步调度预算保护，因此 `loop { if (...) { ... } }` 不能借假分支无限等待冷却或卡住模拟。第十二关可先用有限 for 扫描角度、只在发现目标时更新瞄准方向，再由外层循环执行实际射击动作。下文“必须写 else”的限制描述第七关初次实现时期的语法，以本节更新为准。

## 语言接口

`ProgramParser.parse(source, allowed_calls, allow_tick, allow_named_calls, allow_loops, allow_conditionals=false)` 在末尾新增可选参数，已有调用签名兼容。关卡元数据的 `allow_conditionals` 缺省false、严格布尔校验，前六关原JSON不改动。

显式 `ConditionNode` / `ReadyNode(receiver)` 描述条件，`IfNode(condition, then_body, else_body)` 描述分支；条件不是动作调用，不展开源码。只支持 `if (模块名.ready()) { ... } else { ... }`，需要具名调用权限和射击能力。两个分支都不能为空，必须写else；本阶段不支持通用比较、变量、逻辑运算或任意属性查询。

运行前预检所有真假路径、真实模块名及能力，未选中的分支也不能隐藏错误。条件在进入分支时重新求值，不把启动时的值缓存到之后的循环；执行整个已选分支后才离开。main允许分支和循环，tick允许有限分支，但仍禁止move与loop。64KiB源码、4096token、512调用、1024语句上限延续，if与loop共享16层控制结构预算；拒绝循环引用与非法公开AST。

## 就绪查询与执行顺序

`SimulationWorld.is_shoot_ready(machine_id, module_id) -> DataResult` 必须查询非空名称的存活射击模块。`value` 为 `tick_index + 1 >= next_shoot_tick`，与接下来提交动作的tick一致。查询不提交动作、不推进世界、不修改冷却、弹丸、地图或模块状态。错误保留查询的源码行列。

第七关工作台冷却状态同样使用下一动作tick，避免界面还显示冷却而if已经选择射击。旧关卡的显示方式不改变。一个条件为真只说明当前查询就绪，同一tick重复查询不会预留枪；实际射击仍经过共享冷却检查，不能通过重复回调额外发射。

Runner使用有界执行帧，每次step至多推进一个世界tick。条件选择和块切换不消耗模拟时间，但每个合法分支最终有动作，不能产生空转循环。同步高亮回调受原有取消和重入保护。暂停保留状态；停止、重置和失败取消执行器；重新运行创建新世界。重置代码恢复空框架，工作台撤销及自动保存沿用现有流程。

## 敌人、配置与伤害

`advance_attack` 是显式注册的新行为：每tick按移动速度提交一个有限短移动，同时提交近战tick动作。仍走原有完整运动扫掠；碰墙不积压命令，驱动失效可取消旧移动，但可用近战仍能攻击。没有新增机器碰撞、寻路或任意脚本执行。

`properties.move_angle`、`attack_angle` 是必需有限数字，不需要有限 `move_distance`。可选 `module_health` 对象最多256项，键必须引用此敌人装配实例，值为0.01..1000000。创建世界后只覆盖对应 `ModuleInstance.max_health/health`；共享ModuleDefinition、玩家、其他敌人和地图原文不修改。旧行为不应用此覆盖。血条继续按实例health/max_health比例绘制。

所有攻击仍在同tick末统一结算，不能靠移除敌人行为让其本帧已发出的攻击消失；同帧双方全部被毁按现有失败优先级判定。通关使用既有destroy_enemy目标，存档/编辑器试玩隔离规则不变。Schema保持版本1和扩展字段兼容。
