# 首次通关加权通过率

通过率为「成功权重之和 ÷（首次通关数＋首次通关前的失败次数）」。没有已结算尝试时显示 `—`。手动停止、离开关卡和地图编辑器测试不算失败。

同一关卡首次成功前，真实编译或运行失败继续计入分母。首次成功只增加一次成功及对应权重，之后的成功与失败都不再改变该关卡的通过率记录；重新打开应用后同样生效。教学、未来正式关卡与玩家关卡都参与，来源分类与关卡 ID 共同确定身份，改名或移动文件不能获得新的名额。

| 提示档位 | 权重 |
| --- | --- |
| 无 | 100% |
| 一般 | 50% |
| 多 | 30% |

首通前经历的最高提示档持久保存；中途关掉提示不能抹掉已经使用的辅助档位。

| 原始地图敌方整机数 | 权重 |
| --- | --- |
| 0 | 40% |
| 1—4 | 60% |
| 5—8 | 85% |
| 9 及以上 | 100% |

敌人数使用关卡完整的有效敌方机器清单，包含尚未出场的波次，排除关闭敌人功能时保留的配置和不参与模拟的未知行为条目；不按模块数或当前存活数计算。两个权重相乘：例如「多」加零敌人为12%；若此前失败一次，则该关首通后对总体分子贡献0.12，分母贡献2。

逐关记录作为玩家档案版本1的可选 `statistics.level_ledger` 保存。旧档案没有按关身份和提示档位，无法可靠反推首通记录，因此旧成功/失败总数保留，新通过率从更新后重新累计。UID、姓名、累计游戏时间、提示使用数、彩蛋记录和原耗时数据不受迁移影响。重复游玩的真实活动时间与提示使用仍照常累计；耗时记录沿用原有挑战计时规则。

删除玩家档案会清空逐关记录并生成新 UID；不会删除地图。模型使用有界字段校验和原子替换，保存失败保留原文件与有效内存。统计目录不与地图、通关进度或代码草稿共用文件。
