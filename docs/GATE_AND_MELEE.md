# 限时闸门与近战破障

更新于 2026-09-11，按用户最新指定的 [ProgramLevel.md](https://github.com/yuhan2680/ProgrammableModule/blob/main/ProgramLevel.md) 实现第二、三关。文档只规定限时闸门、两模块速度叠加、第三关右侧 5 单位障碍与 2 单位近战；本工程将具体落闸时间设为 3.5 秒。

## 第二关

- 地板仅一行：`y=3, x=1..10`。出生 `(1.5,3.5)`，终点 `(9.5,3.5)`，全程向右 8 格。
- 闸门为正方形，中心 `(7.5,3.5)`，边长 1，覆盖 `[7,8] × [3,4]`。
- 第 35 tick **开始时**落闸。暂停不推进，停止或重跑重新打开。编辑和组装耗时不计。
- 移动模块速度相加。两个横向模块在第 34 tick 已全部越过闸门，40 tick 抵达终点。一个模块被落下的闸门挡住。
- 落下时与任一可用模块正面积交叠，立即失败；刚好接触边缘允许。失败优先于目标达成。
- 已落下闸门参与每个模块的完整连续扫掠，不能高速穿过，也不能从通道外的 void 绕过。

## 第三关

- 出生 `(1.5,2.5)`，障碍物中心 `(6.5,2.5)`，正好右侧 5 格，边长 1、耐久 1。
- 上限两个模块，允许 `movement` 和 `melee`。推荐中心移动模块与右侧半格共边近战模块。
- `move(0,3)` 后 `attack(0)`，30 tick 移动＋1 tick 攻击完成。到达附近不会自动通关，必须摧毁指定对象。
- `attack(angle)` 是全机指令：所有可用近战模块各自从真实中心沿绝对方向发出射线，不转动机身；内置射程 2、伤害 1，尺寸 0.5 × 0.5。
- 射程到目标表面的首个交点计算，恰好等于射程可命中。前方 void、不可通行地块、已落下闸门和其它未破坏对象阻挡射线，不穿透。
- 一次攻击消耗一个 tick，挥空也正常完成；所有调用串行。没有另加攻击冷却系统、投射物或敌人伤害规则。
- 所有提案读取 tick 开始时的对象与机器位置，再统一提交；同 tick 多次命中累加伤害。对象本 tick 被打破时，同 tick 已计算的移动仍按原阻挡状态执行，下 tick 才能穿过。
- 重新运行建立独立世界，重置耐久；不改写模块定义、地图对象 JSON、编辑器原文档。

## JSON 兼容与示例

继续使用地图 `format_version: 1`。旧地图无 objects 或含未知对象时保持兼容；未知对象作为元数据保留。已实现类型会严格验证 id、图内正方形和属性；不允许任意脚本路径。

在完整地图的 `objects` 数组内添加：

```json
{
  "id": "speed_gate",
  "type": "timed_gate",
  "position": {"x": 7.5, "y": 3.5},
  "size": 1,
  "properties": {"close_after_ticks": 35}
}
```

```json
{
  "id": "training_obstacle",
  "type": "destructible",
  "position": {"x": 6.5, "y": 2.5},
  "size": 1,
  "properties": {"max_health": 1}
}
```

`size` 是正方形边长，省略默认 1，范围 `(0,256]`；完整对象必须在地图内。闸门 tick 为 `1..1000000` 整数，耐久为 `(0,1000000000]` 有限数字。数值字段不接受布尔值或字符串。动态对象覆盖在地板之上，不会自动生成可通行地板。

破障目标放入 `properties.level.goal`：

```json
{"type": "destroy_object", "object_id": "training_obstacle"}
```

`object_id` 必须引用本地图 `destructible`；未知 goal 类型报错。旧 `{position,radius}` 目标继续有效，也可显式写 `type: reach_position`。省略 goal 或 null 为沙盒。

模块定义使用可信 `script_type: MeleeModule`，`properties.range` 范围 `(0,256]`，`properties.damage` 范围 `(0,1000000000]`。各模块 ID 仍由 `allowed_modules` 控制；允许 MeleeModule 的关卡解锁 attack，实际未安装可用近战时，运行器在任何移动前拒绝整份程序。

## 编辑与维护

地图编辑器的“元数据 JSON”可以编辑上述 objects 和 goal；保存、撤销、重做、未保存快照测试继续复用原流程。编辑画布显示打开的闸门与未损坏的障碍物，游戏画布显示本次运行状态。对象与近战图标为仓库内原创 SVG。

此版保留旧关卡 ID、玩家草稿和已完成标记。重新进入关卡仍为空装配；不会自动覆盖玩家代码。旧第三关的转弯程序需要按新关卡说明修改。

关键回归在 `tests/campaign_runner.gd`，布局回归覆盖两种语言与最小窗口。运行 `tools/test.ps1 -GodotPath /path/to/Godot` 或 Python 等价入口进行完整验证。
