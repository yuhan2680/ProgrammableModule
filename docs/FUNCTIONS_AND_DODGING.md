# 第十一关：巧能躲避

按 `ProgramLevel.md` 的第十一关要求，新增函数封装与五次闪避教学。第十关现已补齐随机追猎复习，本关保持 `level_011` 和 `order: 11`；第十一关继承 `constant` 常量、`variable` 变量与赋值，并按用户最新要求直接开放玩家雷达模块和扫描指令，不要求先通关第十关。旧文档的 `value` 是 `constant` 兼容别名。中文本土化名称为“第十一关 · 巧能躲避”。

## 场地和目标

正式定义位于 `data/levels/level_011.json`。地图为 15×13，内部连续地板为 x=1..13、y=1..11，其余位置仍为 void。玩家出生在 `(4.5, 9.5)`，最多安装两个模块。推荐中心测距或雷达 `sensor`，右侧偏移 `(0.5, 0)` 安装移动 `drive`；游戏仍从空装配进入，出生模板不自动安装。

敌人 `radar_hunter` 出生在 `(10.5, 9.5)`，包含前方近战 `blade`、移动 `engine`、后方雷达 `radar` 三个真实部件。玩家也可安装雷达并调用 `scan()`；玩家扫描不改变这个敌人的行为、能力、恢复时间或伤害判定。

目标定义：

```json
{"type":"dodge_attacks","enemy_id":"radar_hunter","attack_count":5}
```

只有目标敌人实际完成并落空的攻击才计数。扫描、靠近、恢复、取消动作和失效模块都不增加闪避次数。该敌人只要一次近战命中玩家的任意部件，本次练习立即失败；不必等待整台玩家机器被摧毁。摧毁敌人不能替代五次闪避。90 秒时限、暂停、重试、通关取消循环均由现有会话和固定 tick 模拟处理。

## 锁定和攻击节奏

注册行为 `radar_lunge` 每轮扫描一次玩家当前位置并固定该位置。敌人先移动到锁定位置右侧的准备点，再向左接近，近战模块中心在锁定位置右侧一格时停下，随后下一逻辑 tick 立即向左攻击。正在接近时不会跟着玩家侧移不断重新瞄准，玩家可通过测距发现靠近，并提前离开攻击横线。

准备点到攻击点的接近距离为 3 格，单移动模块速度保持每秒 1 格，实际移动与模块占地遵循通用碰撞规则，不瞬移。每次出手后恢复 10 tick，再扫描新位置开始下一轮。`attack_module_id`、`radar_module_id`、`attack_angle`、`stand_off`、`approach_distance` 和 `recovery_ticks` 均来自敌人的 JSON 属性。

`SimulationWorld.get_enemy_attack_status(id)` 提供显示所需的只读状态：`phase`（tracking/approach/attack/recover）、`dodged`、`attempts` 和 `next_scan_tick`。界面用同一世界的状态展示攻击节奏和闪避进度，不自行推进计时或凭动画计分。

## 函数语言范围

`allow_functions`、`allow_variables` 与 `allow_radar` 为独立布尔权限，缺省均为 false；前九关保持锁定。本关保留之前已经学过的命名模块、循环、条件、并行动作和测距能力，并开放函数、继承的常变量与玩家雷达扫描。

使用 `function 名称() { ... }` 在顶层定义无参函数，再以 `名称()` 调用。函数可写在 `main()` 前面或后面，执行完返回原调用位置继续运行，不接收参数或返回数值。常量可保存固定的闪避阈值，变量可保存并更新测距数值或扫描快照；函数每次调用创建局部作用域，并可读取全局常变量。完整规则见 [VARIABLES.md](VARIABLES.md)。语言继续使用独立词法、语法、AST、运行器和行列错误定位，不通过字符串展开实现。

初始程序仅展示空的 `main()` 与 `function dodge()` 框架。七页引导说明装配、扫描锁定、函数定义与调用、循环测距、闪避目标和暂停重置，不在初始源码填写完整答案。

## 开发回归参考

以下解法只用于文档和测试；不会作为初始代码交给玩家：

```text
main() {
    loop {
        dodge()
    }
}

function dodge() {
    if (distance(0) < 2.5) {
        move(90, 1)
    } else {
        move(0, 0)
    }
}
```

中心测距、右侧驱动的装配使函数可以从右侧读到来袭近战部件，并在敌人到达攻击点前侧移。每次运动完成后才重新判断，`move(0, 0)` 是合法的零距离动作，用于等待下个逻辑 tick，不会移动机器。读数是传感器中心到目标表面的距离，修改装配或阈值后仍需重新考虑反应时间和模块占地。

`tests/dodge_level_runner.gd` 使用正式 JSON 和公开装配接口验证：生产解法与具名版本可通关、五次独立出手事件与闪避计数一致、敌人连续移动、站桩首次受击立即失败、带常变量和函数局部测距的程序可暂停与重试通关、能力失效与取消动作不刷分、超时失败、旧关卡权限关闭、缺失第十关与严格 JSON 输入校验。所有试运行在内存中完成，不读写玩家存档；源码、装配草稿和地图模板在成功、失败及重置时保持正确边界。


## 雷达装配方案

保留两模块上限，将中心测距模块替换为雷达也可练习本关。`sensor.scan()` 返回最近可见敌机的快照；先判断不为 null，再比较 `target.Distance`。雷达距离是部件中心到敌机参考点的直线距离，和 `distance(角度)` 到第一阻挡表面的射线距离不同，不能把两种阈值当作相同的物理含义。每次需要新状态时重新扫描，保存的快照不会自动更新。

`data/hints/level_011.json` 在原测距方案外提供雷达方案，按当前实际模块行为和名称选择，再通过独立游戏会话验证完整目标。装配帮助同时列出两种选择，不要求玩家为了使用提示拆掉已合法安装的雷达。`tests/player_radar_level_runner.gd` 覆盖正式关卡雷达解锁、真实扫描解法与原有测距解法的兼容；底层与语言契约见 [玩家雷达](PLAYER_RADAR.md)。
