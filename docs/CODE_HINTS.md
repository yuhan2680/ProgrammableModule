# 逐步代码提示

代码提示使用 `CodeHintService.next_hint(session)` 为当前教学关卡返回一次小步修改。它与编辑器的灰字 Tab 补全独立：Tab 补全只完成正在输入的词；代码提示提供经过真实关卡模拟验证的下一条完整动作或控制结构。

## 交互与服务边界

设置提供 `none`（无）、`normal`（一般）和 `more`（多）三档，默认一般。一般档在该教学关卡连续失败三次后显示入口；多档从开始即可显示；无档关闭入口。档位独立保存到 `interface.code_hints`，旧设置缺字段时采用一般，不影响默认开启的 Tab 补全。

连续失败次数按关卡保存在 progress 的 `failure_streak`，退出重进或重启后继续累计；成功通关清零，手动停止和重置位置不增加也不清除已有次数。`GameSession` 每次真实失败只计一次，`GameShell` 恢复并通过 `GameDraftStore` 保存记录；导入和编辑器测试不参与。按钮可见性、加载状态、源码应用、滚动高亮与撤销由 UI 处理，服务本身不保存这些状态。存储字段见 [关卡与存档](GAMEPLAY_DATA.md)。

```gdscript
var result := CodeHintService.next_hint(session)
if result.is_ok():
    # UI 在一个撤销事务中应用整段返回源码。
    var amended_source: String = result.value.source
    var highlighted_line: int = result.value.line # 从 1 开始
    var feedback: String = result.value.message
else:
    # 给出缺少模块、装配位置、资料缺失或结构修复的可执行说明。
    var feedback := "\n".join(result.errors)
```

代码提示仅用于正式教学关卡。所有导入地图与地图编辑器测试都不提供提示，即使它们的 ID 和地图内容与正式教程完全相同。服务要求 `LevelDefinition.source_path` 精确等于 `res://data/levels/<id>.json`，并继续核对完整地图内容；空路径、`user://` 路径、其他资源目录和不同关卡路径都不能通过。UI 同时根据教学来源与编辑器测试模式控制入口。

运行或暂停时不能修改正在执行的程序。已成功的会话、或尚未运行但实际已经能通关的源码，不会反复插入提示。

提示按钮旁提供样式一致的 SVG 撤销按钮，用于撤销最近一次提示所做的修改。UI 将一次提示作为独立撤销事务，只有最新提示仍处于编辑器撤销历史顶部时才提供该按钮；玩家之后的手工修改必须保留，不能跨过这些修改或用提示前的旧快照覆盖它们。常规编辑器撤销仍由原有历史管理。

## JSON 方案

`data/hints/` 当前包含十一份资料，对应 `level_001` 至 `level_011`，包括第十关“猎人游戏”。每份文件只含数据及本游戏 DSL 源码；不会执行宿主脚本、加载任意脚本资源或联网。

```json
{
  "format_version": 1,
  "level_id": "level_007",
  "assembly_help": "请在中心安装移动模块，射击模块放在右侧 (0.5,0)。",
  "bindings": [
    {"role": "gun", "behavior": "ShootingModule", "index": 0}
  ],
  "source": "main() {\n    loop {\n        if ({{gun}}.ready()) {\n            {{gun}}.shoot(0)\n        } else {\n            move(180, 0.1)\n        }\n    }\n}\n",
  "max_steps": 1000
}
```

| 字段 | 约定 |
| --- | --- |
| `format_version` | 当前为整数 `1`。 |
| `level_id` | 与内置教学地图 ID 一致。 |
| `source` | 完整可通关的参考 DSL，仅用于验证与逐步比较，不整段覆盖玩家代码。 |
| `assembly_help` | 方案无法用于当前装配时的具体模块与偏移指导。 |
| `bindings` | 将 `{{role}}` 替换为实际玩家模块实例名；按已注册行为筛选，再按偏移 X、Y、实例名排序选择 `index`。 |
| `max_steps` | 此方案独立验证的逻辑步数预算；通常 1000，第九关长路线为 2200。服务硬上限 2400。 |
| `function_name` | 可选默认函数名。第十一关使用 `{{function}}`；若玩家已有唯一无参自定义函数，保留该名字并同步补齐调用。 |
| `alternatives` | 可选方案数组，最多 16 项；每项提供 `source`、`assembly_help`、`bindings`，继承主方案的关卡身份、函数名和预算。根据真实装配选择可绑定方案，然后仍须通过完整模拟验证。 |

每关参考程序取自已有的整关回归解法。第五、八关的左右近战通过真实位置识别，不要求用户必须命名为 `left`、`right`；第七关射击、第九和十一关测距也使用实际实例名。第十一关另有中心雷达配右侧移动的扫描方案，选择它时绑定实际雷达名称；模块上限仍为两个，原测距方案保持可用。

JSON 方案只绑定正式内置教学关卡，不为导入地图提供加载入口。教学来源通过后，仍将当前关卡完整地图快照与正式 `data/levels/` 定义比较，任何地图内容或目标变化都会拒绝原关提示；不能仅凭相同 ID 套用答案。

## 验证与源码修改

1. 严格核对正式教学来源路径，然后读取有大小及类型检查的 JSON，核对完整关卡内容与实际装配规则。
2. 根据真实模块行为和名称选取并绑定完整参考程序；第十一关支持测距或雷达方案，保留唯一已有函数名。
3. 创建独立 `GameSession`，深拷贝玩家装配，运行完整目标程序。只有真实目标成功，方案才有资格产生提示。速度不足、模块朝向 / 偏移不适合、缺少能力等情况返回装配说明。
4. 同样独立验证玩家当前源码；如果已有另一种正确解法，保留它而不提供多余修改。
5. 以保留原始字符位置的轻量花括号树定位第一处差异，插入或修正一条逻辑行。新 `main`、函数、`loop`、`if`、`simultaneously` 结构配齐闭括号；`if` 可连带空 `else` 框架，但不一次填满分支中的动作。

服务只返回修改后的源码、实际行号与说明，不写入传入会话的 `source`、`assembly`、`world`、运行状态、失败计数或玩家文件。克隆会话不连接原会话信号，执行后解除运行引用。一次点击最多进行两次有界模拟，总墙钟预算为三秒；源码与资料分别限制 64 KiB，编辑树最多 512 个节点。UI 应仅在点击时调用，不在每帧或悬停时反复验证。

原有注释、CRLF 换行、未参与方案的顶层函数、合法常量 / 变量声明与赋值均保留。已有正确的后续动作前缺少一步时，优先插入缺失动作。单条多余动作可转为带原文的注释；额外控制块和无法安全定位的多余括号返回整理说明，不整块删掉玩家的控制流程。提示不是任意程序的自动修复器，保留的额外代码仍可能需要用户检查。

## 回归

`tests/code_hint_runner.gd` 从正式十张地图和各关真实手工装配开始，多次应用一步提示后独立跑通实际目标，并覆盖：

- 一次只补一条动作 / 控制结构，完整参数与返回高亮行。
- 正式初始程序、不同花括号风格、原注释、CRLF 和已有正确步骤。
- 实际模块改名、唯一自定义函数改名、常量 / 变量 / 赋值及无关函数保留。
- 第十一关测距 / 雷达装配选用对应方案；其他缺少所需能力、单移动模块速度不足、测距模块横向装配等实际不可通关情况。
- 相同 ID 的改版地图、完整相同的导入副本、空来源 / `user://` / 非正式资源来源、运行 / 暂停 / 成功状态及源码预算。
- 真实失败世界、失败次数、玩家源码、装配与原会话信号保持不变。

引擎回归命令：

```powershell
godot --headless --path . --script res://tests/code_hint_runner.gd
```
