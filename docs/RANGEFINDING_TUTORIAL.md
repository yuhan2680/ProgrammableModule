# 第九关：蜿蜒穿行

本关按 `ProgramLevel.md` 引入测距模块和 `distance(angle)`，最多两个模块，以长蛇形隧道练习根据当前通道长度行动。新模块 ID 为 `rangefinder`，行为为注册的 `RangefinderModule`。不引入第十关的变量、常量或更后面的雷达设计。

## 关卡与装配

- 稳定 ID `level_009`；中文名「第九关 · 蜿蜒穿行」，英文名 `Level 9 · Winding Passage`。
- 地图为 24 × 22，五段两格宽的水平通道由交替位于左右端的两格宽连接道相连。未绘制区域保持 void。
- 出生点 `(2.5, 18.5)`，终点 `(21.5, 2.5)`，终点半径 `0.25`。没有敌人、计时限制或额外机关。
- 先在中心 `(0,0)` 安装测距模块 `sensor`，再在下方偏移 `(0,0.5)` 安装移动模块 `drive`。两者宽高各半格，沿边连接。
- 每次进入仍从空装配开始。JSON 出生模板只服务底层数据格式，不自动安装模块。初始程序只有空 `main()` 框架，完整答案仅在本文和回归测试中。

## 测距与余量

`distance(angle)` 返回测距模块实际中心沿指定方向到第一个阻挡表面的距离，单位为格；`sensor.distance(angle)` 指定具名实例。方向沿用 0° 右、90° 上、180° 左、270° 下。未命名调用要求恰好一个可用测距模块；多个可用模块时须用名称选择。自身机器的模块不遮挡读取。

查询只读，不移动机器、不发射射线武器、不消耗逻辑时间或改变冷却。查询值在相应动作提交或条件判断时根据当时世界读取；它不是地图静态尺寸，也不是预先计算整条路线。

查询是一条细射线，并不等于整台机器可移动的距离。测距从模块中心开始，实体运动仍检查所有模块矩形与完整路径；不同装配需要不同余量。推荐布局中向右、向左和向上各减去 `0.5` 格后移动，可以停在下一条通道的中心线上。若直接移动完整读数，或把移动模块放到传感器右侧仍使用同一余量，实际碰撞会正确阻止机器穿墙。

本关的参考路线：

```text
main() {
    loop {
        move(0, distance(0) - 0.5)
        move(90, distance(90) - 0.5)
        move(180, distance(180) - 0.5)
        move(90, distance(90) - 0.5)
    }
}
```

每段都重新测量；循环的方向顺序表达隧道的重复形状，数字无需写死为地图中的路程。最后一次右移经过终点即由会话停止循环。数值查询也可用于 `if` 比较，例如 `if (distance(90) > 0.5) { ... }`。查询不能独立作为动作语句；本关只扩展数值查询、加减与比较，不开放变量和任意脚本执行。

## 数据接入与兼容

`properties.level.allow_distance` 必须是布尔值，省略时默认 `false`。前八关地图保持原样，继续拒绝新测距语法；本关保留已学模块以及 tick、具名调用、loop、if 和 simultaneously 的解锁状态。

指令集合从 `data/commands/110_distance.json`、`111_named_distance.json` 读取说明、语法与权限；两项均归属于测距模块查询。中文七页教程、选关说明、工作台提示与名称提供对应英文，玩家代码和命名不自动翻译。

## 验证

`tests/rangefinder_level_runner.gd` 通过真实 `GameSession` 覆盖九关收录、新旧权限、空装配、两模块上限、普通及具名测距通关、缺传感器和无效接收者、错误余量/横向装配的真实碰撞、空框架未通关、暂停恢复、重置重试、终点只通知一次和地图快照隔离。

测试还把全部水平通道缩短两格，并更换测试关卡 ID、终点，使用完全相同的导航源码再次通关，确认行为来自实时测距，而非固定关卡坐标或预填路程。所有运行只使用内存会话和隔离的测试导入目录，不访问正式草稿、完成记录或设置。
