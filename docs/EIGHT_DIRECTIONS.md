# 第十二关：八方来敌

本关练习用有限 `for` 循环扫描八个方向，再把测量结果用于射击。推荐在场地中心安装命名为 `sensor` 的测距模块，在右侧 `(0.5,0)` 安装命名为 `gun` 的射击模块，原地防守。模块上限为两个；此前已解锁的移动、近战、射击、测距和雷达仍全部可选，不会因推荐方案重新锁定。

地图包含八波敌人，依次从 0、180、90、270、45、225、135、315 度接近。每波只有一台真实机器，由近战模块和移动模块组成。前一台的全部可用模块都被击毁后，等待短暂逻辑时间，再出现下一台；八波全部完成才通关。敌人会真实移动并攻击，不防御会导致失败，不能靠空等完成目标。

## 推荐程序与扫描节奏

初始代码继续保持空 `main()` 框架，程序不预填答案。以下是开发文档中的参考结构，具体关卡的逐行提示仍通过独立模拟验证后提供：

```text
main() {
    variable aim = 0
    loop {
        for (angle in 0..315 step 45) {
            if (sensor.distance(angle) < 6) {
                aim = angle
            }
        }
        gun.shoot(aim)
    }
}
```

`for` 每轮依次使用八个角度，不会自动移动模块。测距和赋值只读取、记录当前世界状态；扫描完成后的一次 `shoot` 动作推动模拟继续。把射击放在 `for` 外，可以先检查全部方向，避免在前几个空方向的射击冷却中拖延检测。没有发现新的目标时保留上次方向，下一轮会再次扫描。子弹仍受实际枪口、弹道、射程和冷却约束，不会因写了 `shoot` 就直接扣除敌人耐久。

`if` 可省略 `else`；条件不成立时直接继续后续语句。循环角度与游戏一致：0° 向右，90° 向上，180° 向左，270° 向下，45° 的倍数补足斜向。测距仍从测距模块自身中心出发，不是整台机器的中心；雷达也不会替代这个查询来源。

## 有限循环的权限与边界

`properties.level.allow_for` 是独立可选布尔字段，缺省 `false`，第十二关显式开启，前十一关维持原权限。正式会话把该权限交给 Parser；直接构造 AST 的工具仍须先使用正确关卡权限解析源码。

语法为 `for (变量 in 起点..终点 step 步长) { ... }`，省略 `step` 时步长为 1。达到区间终点时包含该端点；若步长不能恰好落在终点，则停在越过终点之前。负步长可用于倒序，但不得为 0，也不得朝远离终点的方向。起点、终点、步长在每次进入循环时各求值一次，不能在预检时执行随机函数或世界查询。循环变量是每轮块内的只读局部绑定，不能赋值，也不能从循环外引用。

单次进入最多执行 4096 轮，仍受现有嵌套深度、源码复杂度和非动作步数预算保护；暂停保留当前迭代、动作与作用域，重试从初始状态重建。`for` 不允许放入 `tick()` 或 `simultaneously`；不开放宿主循环、`while`、反射、任意脚本执行或无限制空转。常变量、条件、测距、函数和随机工具继续遵守各自独立权限。

## 分波地图配置

新注册敌人行为为 `wave_approach_attack`，不是任意脚本入口。它沿用普通接近后攻击的真实移动与近战命令，另由 `EnemyWaveController` 控制出生与完成顺序。

| 敌人 properties 字段 | 约束与含义 |
| --- | --- |
| `wave_order` | 1..64 整数；全图唯一，并从 1 连续编号 |
| `spawn_delay_ticks` | 0..600 整数；首波从世界 tick 0 起等待，后续波从前波真实完成时起等待 |
| `move_angle` | 有限数字，沿游戏角度方向接近 |
| `move_distance` | 0..512 有限数字，有限的真实接近距离 |
| `attack_angle` | 有限数字，接近结束后的真实近战攻击方向 |
| `module_health` | 可选实例耐久覆盖；键必须引用本敌人已有模块，值为 0.01..1000000 |

行为必须包含真实移动与近战模块，不添加新玩家模块，也不修改共享模块定义。多个波的 JSON 数组顺序不影响执行，实际按 `wave_order` 排序。未知行为仍只作为地图元数据保留，不会因包含波次字段而获得执行能力。

加载时校验全部未来出生实例的模块占地、void、地图边界和实体障碍；激活时再次按当时世界状态检查出生点。如果后续机关导致出生位置不可用，报告失败，不能穿过机关或跳过这波。待生敌人不进入 `world.machines`，因此运行中的绘制、雷达、测距、碰撞与弹丸全部看不到它们；不能提前对未来波次扣血。静态地图预览可按文档显示出生位置，不代表这些敌人已进入运行世界。

## 几何、伤害与目标

推荐装配的测距中心为 `(0,0)`，枪口为 `(0.5,0)`，二者相差半格。敌人的八条径向接近线以两者中点为基准：北、南来敌沿玩家 X 加 `0.25` 的直线接近，测距射线与枪口射线分别穿过敌人真实矩形的两侧边缘；斜向同样使用这个中点，后方移动模块采用半格偏移。正方向坐标保持精确，避免三角函数尾数导致边缘射线落空。

这些安排只改变关卡装配与出生数据，不扩大通用模块尺寸或命中盒，也不隐藏执行补偿。敌人模块是否被毁以统一伤害提交后的真实 `available` 状态为准，单个模块被毁不足以跳到下一波。玩家、敌人的移动与攻击共用同一 10 Hz 逻辑时钟；暂停时出生等待、位移、子弹与冷却都不推进，重试重建全部八波。

关卡目标 `destroy_waves` 读取全部波次完成状态，包含尚未出场的敌人。过渡等待时没有活敌人，并不等于通关；最后一波所有模块被击毁后才满足目标，玩家失败仍由既有会话失败检查处理。

`SimulationWorld.get_enemy_wave_status()` 对普通关卡返回空字典，对分波关卡返回独立快照：

| 字段 | 含义 |
| --- | --- |
| `total` | 本地图总波数 |
| `completed` / `defeated` | 完整击毁的波数；两字段相同 |
| `spawned` / `pending` | 已激活波数 / 尚未激活波数 |
| `current` | 当前或下一波序号，最后完成后停留在总波数 |
| `active_enemy_id` / `active` | 当前活动敌人的 ID / 是否有活动波 |
| `next_spawn_tick` | 下一波截止 tick；活动中或全部结束时为 -1 |
| `all_cleared` | 存在波次且全部完成 |

UI 仅消费此快照显示波次与等待状态，不会通过读取状态推进世界、激活敌人或改变伤害。完整快照每次新建，调用方修改返回字典不能篡改控制器。
