# 玩家雷达与目标快照

第十关“猎人游戏”开放玩家雷达和扫描，与移动、射击组合为三个模块的综合复习；常量与变量可选。第十一关“巧能躲避”继续继承这些能力并增加函数，模块上限仍为两个。前九关保持原权限，解锁不依赖其他关卡的通关记录。

## 解锁与实际能力

第十一关在 `properties.level` 中同时配置 `allow_radar: true` 和 `allowed_modules` 中的 `radar`。`allow_radar` 是独立布尔权限，默认 false；错误类型被拒绝。扫描来源必须实际安装且存活，允许列表中出现模块并不能代替装配。雷达静态配置来自 `data/modules/radar.json`，当前 `radar_range` 为 32 格；定义校验要求范围为大于 0、最多 512 的有限数字。

`scan()` 不带参数。有且只有一个可用雷达时可使用裸调用；有多个可用雷达时须用 `模块名.scan()` 指定来源。具名形式还要求 `allow_named_calls`，实例名必须真实存在且具备雷达能力。损毁、停用、缺少雷达或来源歧义都会返回可定位的错误，不会假装成“没有目标”，也不会替换为其他模块。

保存扫描结果需要 `allow_variables`，条件分支需要 `allow_conditionals`；雷达权限不会自动打开这些权限。第十、十一关已经显式开放它们，用户关卡仍按自己的规则处理。

## 语言用法

```text
main() {
    variable target = scan()
    if (target != null) {
        move(target.Angle() + 90, 0.1)
    } else {
        move(0, 0)
    }
}
```

这是查询和判空的语言示例，并非本关完整答案。目标存在时读取其扫描角度，侧移 0.1 格；没有可见敌人则等待一个动作 tick。`scan()` 本身不消耗 tick，`move(0, 0)` 仍沿用既有零距离动作规则。

| 写法 | 返回内容 |
| --- | --- |
| `scan()` / `sensor.scan()` | 最近可见敌机的本次目标快照；无目标返回 `null`。 |
| `target.Angle()` | 雷达来源中心指向目标参考点的方向角，0° 向右、90° 向上、180° 向左、270° 向下，范围为 `[0, 360)`。 |
| `target.Position` | 扫描当时敌机参考点的世界位置向量，单位为格。 |
| `target.Position.x` / `.y` | 世界横向 / 纵向坐标。x 向右增大，y 向下增大。 |
| `target.Distance` | 雷达模块中心到敌机参考点的直线距离，兼容 `target.Distance()`。 |
| `target == null` / `target != null` | 是否存在目标；`Null` 是兼容拼写。 |

属性名称区分大小写。`Angle()` 必须有空括号；`Position`、`x` 和 `y` 是属性，不加括号。也可以先写 `constant point = target.Position`，再读取 `point.x` 或 `point.y`。常量、变量均能保存数值、有效目标快照、位置向量或 null，保留原有作用域与常量写保护。

目标成员只读，不支持属性赋值。读取前应判断目标不为 null；对空目标读取成员会产生带行列的错误。目标只能与 null 做 `==` / `!=` 判断，不能对两个目标作排序或把它们当作数值。移动、攻击、射击和测距的数值参数，加减及数值比较，继续严格要求有限数字；需要角度、距离或坐标时先读取对应数值属性。

快照记录查询时的位置、角度和距离。敌人或玩家移动后，旧快照不会刷新；再次 `scan()` 才得到新值。声明和赋值复制快照，修改一个绑定不会回写其他绑定或世界。目标的坐标是敌机参考点，不是最近模块边缘；雷达 `Distance` 也不同于测距模块 `distance(角度)` 到首个阻挡表面的射线距离，不能视为整台玩家机器安全移动的距离。

## 世界查询与几何

`SimulationWorld.validate_radar_source(machine_id, module_id = "") -> DataResult` 成功时提供真实 `ModuleInstance`，仅供可信模拟及语言预检选择来源。`query_scan(machine_id, module_id = "") -> DataResult` 成功时返回 null，或每次新建的下列字典：

```gdscript
{
    "enemy_id": "radar_hunter", # 稳定机器 ID
    "position": Vector2(10.5, 9.5),
    "angle": 0.0,
    "distance": 6.0,
}
```

该字典是底层快照格式，不是允许玩家输入任意字典或读取 `enemy_id` 的语法。语言只开放上表中的目标属性，不公开机器实例，也不调用宿主对象的方法。

来源为 `machine.position + module.local_position`，目标为敌机的 `position`。查询忽略自身、同阵营和已失效 / 被碾压的机器；当前世界以玩家和敌人区分两类，敌方扫描仅以玩家为目标。只要机器还有可用部件，就仍是存活目标。多个目标中先选距离最近的可见对象，相同距离按机器 ID 稳定选择；结果不依赖机器数组顺序。

探测范围是以真实雷达模块中心为圆心的圆形半径，端点包含。只有地块 `radar_block` 属性阻断从来源到目标的线段；普通碰撞、void 或其他机器本身不会额外当作雷达屏障。屏障与射线相交且交点在目标之前才阻断，射线外或目标后方的地块不误挡。玩家扫描与敌方 `radar_detects_player()` 共用这一规则，敌人的每轮锁定、实际接近、近战和恢复时间保持原行为。

所有扫描均为只读查询：不推进时钟、不预占冷却、不提交或取消动作、不发送模拟信号，也不修改源地图、运行位置、耐久或敌人状态机。无可见目标是正常空结果，能力错误是失败结果，两者不可混淆。

## 实现边界与界面

Parser 在尾部追加默认 false 的 `allow_radar`，扫描、null 和属性链使用显式 `ScanNode`、`NullNode`、`TargetMemberNode`。Runner 在启动前校验全部代码中的雷达来源，运行时核对固定快照字段、类型和有限值；属性读取使用固定分支，不执行反射、任意成员或用户宿主脚本。表达式深度、节点及纯计算预算沿用现有上限，扫描本身不能让无限纯查询循环绕过执行预算。

组装页的雷达在第十、十一关可选择，引导不再宣称玩家雷达未开放。五份指令 JSON 提供普通 / 具名扫描、角度、位置和距离说明；指令集合与 Tab 补全按当前关卡权限和已装实例提供内容。代码提示资料在第十一关提供测距和雷达两种装配方案，选择后仍通过独立会话验证真实五次闪避目标，不改变两模块上限。

## 回归入口

- `tests/player_radar_world_runner.gd`：实际模块中心、圆形范围、角度、遮挡、最近目标与稳定 ID、阵营、存活状态、返回副本，以及动作 / 冷却 / 时钟 / 信号不变。
- `tests/radar_language_runner.gd`：权限、普通 / 具名查询、快照保存与作用域、判空、固定属性、数值类型边界、全程序能力预检与公开 AST 防御。
- `tests/player_radar_level_runner.gd`：正式第十一关解锁、雷达装配、常变量 / 函数扫描解法、暂停、重试和五次实际闪避。
- `tests/radar_lunge_world_runner.gd` 与 `tests/rangefinder_world_runner.gd`：既有敌方锁定和测距规则的兼容性。

全部测试使用独立内存世界或测试目录，不读取或写入正式玩家草稿、设置或进度。最终执行结果见 [验证记录](VALIDATION.md)。
