# 第六关：循环与阶梯

依据 [ProgramLevel.md](https://github.com/yuhan2680/ProgrammableModule/blob/main/ProgramLevel.md) 第六关：最多一个模块，重复十次的 3×2 阶梯，介绍 `loop {}` 并移动到终点。

## 地图与参考程序

游戏初始程序只提供 `main()` 与空的 `loop {}` 框架，不预填移动或答案注释。中英引导帮助玩家观察转弯与路段长度，由玩家自己编写动作；下面的完整程序仅用于开发参考与回归验证。已有玩家草稿不会自动覆盖，点击「重置代码」可恢复新的空框架。

`data/levels/level_006.json` 使用原地图格式版本1，尺寸33×23，起点 `(1.5,21.5)`，终点 `(31.5,1.5)`，目标半径0.25。51个地板格组成十组连续的右3上2阶梯，其他区域为 void。上限一个模块，推荐在中心安装移动模块；沿用空装配、确认后编程的流程，不自动安装模板。

```text
main() {
    loop {
        move(0, 3)
        move(90, 2)
    }
}
```

每轮移动总长5格，单驱动速度1格/秒，十轮约50秒。loop 是无限重复，不是次数循环；实际到达目标范围时 GameSession 判胜并取消后续动作，不需要第十一轮，也不需要玩家写停止指令。展开相同路线同样可以通关，胜利不通过匹配固定源码判断。

## 格式与语法边界

- 新增可选布尔值 `properties.level.allow_loops`，默认false；第六关开启，前五关保持关闭。没有迁移旧关卡或草稿。
- `ProgramParser.parse` 末尾增加 `allow_loops = false`，现有参数顺序保持兼容。调用权限、tick及命名权限仍独立。
- 显式 `ProgramAst.LoopNode` 保存块与源码位置，BlockNode 保存语句节点。loop不是普通函数调用，也不预展开为固定次数数组。
- 写法 `loop { ... }`，不接受 `loop()` 或 `loop(10)`。循环可放在main中，tick中禁止；本阶段没有break/continue和计数循环。
- 空循环及只含注释的循环报错。命名move/attack/shoot可在循环中使用，但仍要求该关卡解锁相应能力，实例名与真实模块能力相符。
- 解析与公开AST预检限制最多16层循环、512条调用、1024个语句节点（包含loop），原64 KiB源码和4096 token预算保持不变；拒绝非法结构及循环引用。整份程序检查通过后才提交首个动作，后置非法语句不能部分执行。

## 调度与终态

运行前对公共 AST 进行完整预检；start() 后该 AST 视为只读，界面修改源代码需停止并重新编译。执行器使用执行帧保存代码块、语句位置和循环边界。块内每条动作完成后才推进游标，边界回到循环块首；结构遍历不推进世界时间，也不在同一次step内连续执行多条世界动作。

每次 `step()` 至多推进一个真实逻辑tick。包括零距离move在内的真实指令仍按既有规则消耗tick，因此 `loop { move(0,0) }` 不会卡住界面。暂停不调用step，保留帧栈和当前动作；停止或失败清理执行状态。重试创建新世界和执行器，保留玩家源程序与装配。

循环外的tick回调仍可按原有规则运行；短动作、共享模块冷却、全帧统一伤害以及禁止重入的语义延续。到达终点由GameSession结束循环，解释器不识别关卡ID或地形。

## 显示与验证

GameWorkbench按实际观察区域缩放地图，最低每格8像素、最高48。较小的网格上，PlayfieldCanvas用蓝色圆环标示机器人中心；标记尺寸不参与碰撞。SVG缩略图继续根据地图生成，不新增静态编号图标。

`tests/staircase_level_runner.gd` 通过真实关卡、Parser、GameSession验证循环通关、错误步长、暂停/停止/重试、配置校验和前五关语法锁定；语言套件验证循环语法、AST、预算与执行边界。UI/布局检查中英语言、两种窗口、整个阶梯画布可见和保存流程。完整入口为 `tools/test.ps1` / `tools/test.py`。
