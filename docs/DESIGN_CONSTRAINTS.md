# 当前设计约定

本文件记录根据《可编程模块游戏设计》对话与当前需求采用的约定，更新于 2026-09-19。原有 `ProgramLevel.md`、`Mechanism.md` 保留作为历史设计参考；发生冲突时以用户最新要求为准。

## 本阶段

- 保留 Godot 底层、数据加载和地图编辑器，保留现有游戏流程，并提供使用相同底层能力的第一至第十五关，共 15 个教学关卡；第十关使用真实雷达追猎地图。
- 启动显示主菜单：开始、地图编辑器、设置、离开。地图编辑器只保留主菜单入口。
- 关卡选择固定每排七项，默认显示前七项教学关卡，展开后显示全部 15 个；更多关卡向下排列并纵向滚动，导入分类保留独立“+”入口。
- 每次进入关卡先显示独立组装页，初始装配为空；确认装配后才进入带行号的程序编辑页。
- 设置提供主音量、简体中文/ 繁體中文/ English、默认开启的 Tab 补全，以及代码提示「无 / 一般 / 多」（默认一般），修改立即应用并独立持久化。
- 内置玩家内容包含移动、近战、射击、测距和雷达模块；玩家雷达在第十关开放，第十一关继承，该关敌人也有真实雷达模块。地块、限时闸门、可破坏障碍及敌人行为继续使用已注册定义。
- 未指定地块的位置，以及地图边界以外的位置，都是 void。任何机器的实体模块都不能进入或越过 void。
- 模块、地块、地图分别使用独立 JSON；地图仅引用稳定内容 ID。
- 界面使用 Godot 控件与统一浅色圆角主题；替换显示不得改动底层规则。
- 数据定义、运行时实例、行为、世界模拟、编辑文档和显示层分离。
- 代码中的函数附中文用途注释；新功能优先使用明确的小类和普通控制流。
- 新增关键校验、状态切换和调度逻辑也附中文注释，便于后续程序员理解设计原因。
- `allow_random` 与变量、雷达、测距及函数权限独立；第十、十一关开启，旧关卡默认关闭。随机调用复用有限数值表达式入口，支持括号、一元正负号及加减；不增加新模块、乘除法、任意宿主方法或独立动作。正式运行由 GameSession 传入权限给 Parser，Runner 保持 AST 结构、类型与数值范围校验职责，不读取关卡权限。随机选取参数仍须接受原有动作范围、碰撞及能力校验。

## 第一关与玩家流程

- 第一关使用 S 形地板路径，出生位置 `(1.5, 7.5)`，终点 `(5.5, 1.5)`。
- 设计路线为向右 4、向上 3、向左 4、向上 3、向右 4 单位。路径中的未绘制区域仍是 void。
- 只解锁 `movement`，模块数量上限为 1。初始程序展示 `main()` 与少量示例，不填入完整答案。
- 不自动预装地图模板或上次草稿的模块。源程序可以自动恢复；玩家主动点击“载入上次装配”时才恢复已有布局。
- 在同一关卡内点击“编辑模块”返回组装时保留当前程序与装配，停止本次试运行；确认后返回编程，无需重新选关或重置模块。
- 组装页左侧「＋」玻璃目录展示全部已注册模块，介绍默认收起；不允许的类型禁用；满上限后不能新增，已有模块仍可按装配规则移动、命名和删除。
- 装配图自由缩放偏好默认关闭，独立持久化为布尔值。关闭时显示固定完整蓝图与白框，停用滚轮缩放、右键拖图和柔边；开启时恢复自由查看。开关仅控制视图，不改逻辑原点、相对偏移、出生点或草稿。
- 空装配首件可在图纸内任意落格，成功落点成为视觉装配原点；模型中第一个模块中心偏移仍严格为 `(0,0)`，后续模块使用相对偏移。只有一个模块时不能移离该原点，删空后允许重新选点。视觉原点不写入关卡出生坐标或草稿。
- 后续新增或移动必须与任意已有模块的实际矩形边缘共边，接触长度大于零。允许分支，不要求串成单链；角点接触或空隙不算连接。
- 删除中心或桥接模块可以留下不完整草稿。`validate_editing()` 只检查结构、网格、类型、数量、命名与重叠，允许空装配、缺中心和断连，便于保存及手动恢复后继续修复。
- 最终 `validate()` 要求非空、存在中心偏移为 `(0,0)` 的模块，且全部模块沿边连通；`build_document()` 还要校验完整出生占地。缺中心、断连或占地进入 void 时禁用确认按钮，悬停展示原因。直接调用也不能绕过最终校验。
- 玩家修改程序和装配后运行；每次重新运行使用出生状态，不累计上次失败的位置。
- 抵达或经过终点半径范围视为通关。程序结束但未到终点、移动被 void 阻挡，均给出失败原因并允许继续编辑。
- 暂停冻结程序与世界逻辑 tick；恢复继续执行；「重置位置」保留玩家源程序和装配草稿。「重置代码」显式恢复当前关卡的 starter_program 并停止旧运行，保留装配和通关记录，支持撤销；正常关卡更新草稿，编辑器试玩继续保持会话隔离。
- 游戏装配使用 `0.5` 格偏移网格，范围 `-4..4`。模块实例名遵循英文字母或下划线开头、后续字母数字下划线的标识符格式。
- 关卡定义保存在地图 `properties.level`。自定义地图从 `user://levels` 导入，玩家草稿与通关记录存入 `user://solutions`；两者不互相覆盖。
- 地图 `player_spawn.modules` 继续作为底层格式与缺省关卡规则的来源保留；正常关卡和地图编辑器测试都不会自动安装该模板，不需要删除它或改变既有 Schema。
- 音量、语言、Tab 补全和代码提示档位写入 `user://settings.json`，与关卡、程序草稿、通关记录分开保存。
- 无关卡目标的普通编辑器地图可以作为沙盒导入；没有出生点的编辑草稿还不能进入游戏。

## 地图编辑器测试

- 分类折叠只影响可见性，不改变地图、输入值和撤销历史，试玩返回保留折叠状态。「场景编辑」包含尺寸和地形工具；「场景玩法与行为控制」包含起终点、限时、两项玩家上限和敌人设置。
- 编辑器时限默认60秒，必须大于0且不超过3600秒，以0.1秒精度转换为既有 `max_ticks`。保存/测试前提交有效限时，空白与0不能作为不限时；编辑文档事务保留其他规则和扩展数据。
- 编辑器限时模式显式写入 `completion_mode: "reach_or_clear"`，到达坐标终点或清除全部已注册敌人即可通关。初始无敌人不能立即获胜，尚未出现的波次不能忽略。没有终点和敌人也可测试，但仍按截止时间失败。
- 世界失败先结算，截止tick真实达标允许通关；主程序结束不能停止计时。倒计时仅用模拟tick，暂停冻结、重试恢复。未启用新模式的既有教学和导入地图保持原目标与时间语义。

- 「场景玩法与行为控制」独立放置起点与可选终点，地形下拉不包含出生点。起终点用单击放置，不走拖动或框选批量逻辑；两个红字重置按钮只移除对应内容，支持保存与撤销重做。
- 终点不必添加：无目标地图仍可保存与自由测试；已有战斗目标不能被“重置终点”误删。添加终点复用 `properties.level.goal`，不另建一套通关机制。
- 场景宽高输入限制 `1..64` 整数，键入、粘贴和应用均校验。通用地图格式仍兼容 `1..256`，读取旧大地图不可静默裁剪；模块数量上限不受此输入规则影响。

- 敌人开关保存为 `properties.level.enemies_enabled`；显式关闭保留敌人数组与模板，只阻止运行时生成敌人。旧地图缺省维持原运行行为，打开编辑器不能隐式改写开关或产生历史。
- 敌人模板保存在 `properties.editor.enemy_template`，包含 `module_limit`（1..256 的整数）、`module_health`（0.01..1000000 的有限数字）和非空 `module_ids` 顺序列表；数量不能超过模板上限，模块必须已注册。修改模板不回写已放置敌人的装配或耐久，共享模块定义及玩家耐久不受影响。
- 敌人组合按真实模块宽度横向共边排列，首件偏移为零；地图落点吸附半格，完整模块占地须在地图内的可通行地板上，且不与玩家出生模块、现有敌人或场景对象重叠。加号进入半透明 SVG 预览，左键按下只提交一组；右键或 Esc 取消，缩放、滚动、失焦、隐藏或切换工具清除旧预览。预览不能写入历史；开关、模板和成功放置均通过编辑事务保存、撤销与重做，失败不改地图。
- 新放置敌人只引用已注册的 `auto_chase_attack` 行为，由可信固定 tick 控制器根据真实存活模块提交移动、近战或射击动作；不从 JSON 执行任意代码，不凭空赋予移动或武器能力。地形、碰撞、射程、冷却和部件损伤继续使用现有模拟规则。

- 编辑器的「开始测试」复用正常游戏的空装配 → 确认装配 → 编程流程，不提供直接执行单次 `move` 的表单。
- 测试采用当前未保存地图的独立快照，以及编辑器当前的内容注册表，无需先保存或重新从磁盘读取地图。
- 模块数量上限由编辑器设置为 `1..256`，写入 `properties.level.module_limit`，与其他地图修改一起保存、撤销和重做；每次测试使用当前值。
- 玩家耐久按现有每模块损伤机制工作，显式 `properties.level.player_max_health` 覆盖实际玩家装配中各模块的初始/最大耐久，支持正小数，最大1000000000；不能修改共享定义或敌人。旧地图缺省继承模块定义，新建地图默认1。输入、地图格式、关卡与运行时均拒绝非法值，保存、撤销和试玩遵守同一文档事务。
- 「校验」检查地图和关卡定义。玩家真实装配的中心、连通和完整出生占地在确认装配时检查，不用出生模板的占地提前阻止进入组装页。
- 每次开始测试建立新的空装配会话。同一次测试内切换组装/编程、停止或重置位置会保留当前程序和装配；返回地图编辑器即结束本次测试，下次不会恢复上次测试作品。
- 返回时保留同一个编辑器文档、文件路径、未保存标记和撤销/重做历史，不通过重新打开文件恢复页面。
- 测试期间不读取或写入正式 `user://solutions` 草稿和通关记录，即使地图 ID 相同也不互相影响。界面隐藏保存草稿和载入上次装配；自动保存和完成事件不落盘。
- 独立运行 `scenes/map_editor.tscn` 同样由 `GameShell` 包装编辑器；编辑器只发出测试请求，执行与计时复用 `GameWorkbench` / `GameSession`。
- 普通关卡保持原有草稿与进度行为，内置第一至第十五关。`data/maps` 与 `data/levels` 本轮不迁移或合并。

## 已采用的模拟规则

- 世界每秒 10 个逻辑 tick，动作先计算再统一提交。
- 模块默认大小为 0.5 × 0.5 格；模块中心偏移决定真实占地，不允许实体模块彼此重叠。
- 多个移动模块的有效速度相加。JSON 的 `move_speed` 单位为格/秒。
- `move(角度, 距离)` 使用绝对方向：0° 右、90° 上、180° 左、270° 下。
- 地图坐标 x 向右、y 向下，以格为单位，支持连续位置。
- 移动是有限距离动作，遇到不通行地形后停在接触点并报告 `BLOCKED`。
- 当前没有惯性、机身旋转、滑墙或机器之间碰撞。近战按真实射线向可破坏对象与敌我模块结算伤害，敌人只执行已经注册的固定行为。
- 中心与沿边连通约束属于玩家游戏装配层；底层地图格式和 `MachineFactory` 不增加通用拓扑限制。碰撞仍取实际模块矩形的并集，不把空隙填成实体，也不引入额外 Core。

## 后续方向与边界

游戏计划包含战斗模式、设计模式、对战模式。模块决定可调用能力，程序决定行动。不添加统一 Core 模块，也不引入已取消的能源、维修系统。

当前 DSL 已实现单一 `main()` 入口、逐行 `move(角度, 距离)` 与第三关解锁的 `attack(角度)`、数值字面量、空行和 `//` 注释。执行器通过 `SimulationWorld.request_move()` 和命令完成状态顺序等待，不执行任意 GDScript。相邻调用强制换行，不接受分号；错误包含行号。

完整语言仍在后续阶段实现。玩家入口保持 `main()`，不是 `init()` / `tick()`；当前无限循环使用 `loop {}` 并按关卡开放。Lexer、Parser、类 Kotlin 的显式 AST 节点和解释器保持分离。`simultaneously {}` 需要独立的 AST 与调度语义，不应伪装成普通函数调用。上述为早期语言规划；当前已逐关开放循环、条件、有限数值表达式、自定义无参函数、命名模块调用及并发块。第十一关显式开放常量、变量与赋值；绑定可保存数值、雷达快照、坐标或 null，数值动作仍严格要求有限数字；函数参数与返回值尚未开放。当前边界见 [函数复用](FUNCTIONS.md) 与 [常量与变量](VARIABLES.md)。

原始雷达规划中的 `radar.Detected`、`scanAll()` 与 `Target.type` 仍属后续范围，不恢复 `scanAllInfo()`。按用户最新要求，第十、十一关已开放 `scan()` / `模块名.scan()` 及目标 `Angle()`、`Position`、`Distance`；完整规则见 [玩家雷达](PLAYER_RADAR.md)。雷达范围与地块的 `radar_block` 为数据配置，扫描只返回最近可见敌机的当次快照，无目标为 null；玩家查询与敌方锁定共用范围和遮挡语义。

抓取模块未来遵循 `grabber.grab(角度)`、1.5 格范围与 `grabber.Holding` 的设计。上述系统现在只作为扩展约束，不提前实现。

## 2026-09-11：按最新需求恢复第二、三关

用户最新要求恢复 `ProgramLevel.md` 中第二关水平直道与限时闸门，第三关近战模块与 `attack(角度)` 破障教学，取代上一轮“仅使用移动能力”的重设计。第一关仍保留上下对齐的 S 路线；第二、三关最多两个模块。具体坐标、计时、射程、碰撞、目标和 JSON 字段见 [GATE_AND_MELEE.md](GATE_AND_MELEE.md)。

## 第四关扩展

当前内置四关。`LevelDefinition` 新增 `allow_tick`（默认 false）、`max_ticks`（默认 0，不限时）和 `destroy_enemy` 目标；射击调用按允许的模块行为解锁。第四关上限 1、敌人初始位于右侧 6 格，向左移动 4.5 格后近战攻击。

`GameSession` 在战斗主程序结束后继续推进世界；玩家死亡优先于同 tick 敌人全毁的胜利，超时失败，暂停/重试语义不变。`MapCanvas` 只显示敌方模块耐久和子弹；`LevelThumbnail` 从地图敌人数据生成选关 SVG。

语法、敌人 JSON、伤害与冷却细节见 [SHOOTING_AND_ENEMIES.md](SHOOTING_AND_ENEMIES.md)。


## 第五关扩展

`allow_named_calls` 默认 false；第五关显式开启。Lexer 保留小数词法，Parser 使用显式 `CallNode.receiver`，Runner 在提交任何动作前检查所有实例名与能力。世界接口可选 `module_id`，空值保持广播，非空精确筛选能力来源；命名不改变真实模块占地或各实例冷却。

`alarm_guard` 等待警报，`prison_alarm` 在同 tick 全部伤害提交后检查绑定警卫；警卫仍活则立即处决全部玩家模块。`security_gate` 仅在引用的全部已注册敌人和可破坏对象被清除后解锁。`escape_prison` 还要求玩家沿实际路径到达出口；失败先于胜利。

UI 从世界读取 `triggered` / `unlocked` 状态，SVG 和地图缩略图只呈现，不自行控制规则。新增字段兼容 `format_version: 1`；坏引用拒绝，未知扩展仍保留。前四关 JSON、草稿数据及编辑器测试隔离约定不变。


## 第六关扩展

`properties.level.allow_loops` 可选且默认 false，第六关显式开启，前五关 JSON 保持不变。Parser 使用显式 LoopNode，Runner 使用有界执行帧维护 main 的循环位置，不展开源码、不按关卡编号硬编码十次。每个 step 仍只推进至多一个模拟 tick；循环边界本身不消耗世界时间。

循环仅能出现在 main 中，tick 回调仍为有限的 attack/shoot 短动作。整树预检、层级/节点数量限制和空块拒绝避免语法树或结构遍历卡死；零距离移动也保持每次一个 tick。到达目标后由 GameSession 取消解释器，暂停/重试和草稿隔离约定延续。

33×23 阶梯地图采用现有 floor SVG、位置目标与一模块装配，不增加新的模拟对象类型。观察区允许缩小至每格8像素以完整显示本关；小网格的机器人圆环只属于显示，不改变真实占地。详见 [循环与阶梯](LOOPS_AND_STAIRCASE.md)。

## 第十一关边界

第十一关中文名为“巧能躲避”，地图 `level_011` 的 `order` 保持 11；第十关已补齐随机追猎复习，按最新要求用 `allow_variables: true` 继承常变量，并用 `allow_radar: true` 与允许模块 radar 直接开放玩家雷达及扫描指令，前九关保持关闭。两模块装配、空 `main()` 与函数教学框架沿用原游戏流程。函数须显式声明、无参无返回值，禁止递归和空函数；所有函数体仍接受逐关权限与实际模块能力校验。

目标敌人的雷达每轮锁定一次玩家位置，随后按真实移动速度接近到一格前方并立即近战。五次实际落空攻击才完成 `dodge_attacks`；命中任一玩家部件立即失败，取消、受阻、能力失效或摧毁敌人不能冒充闪避。UI、暂停、重试和时限均读取同一个固定 tick 世界。规则与参考数据见 [FUNCTIONS_AND_DODGING.md](FUNCTIONS_AND_DODGING.md)。

## 教学代码提示边界

代码提示仅用于正式教学关卡；导入关卡和编辑器测试即使复用相同 ID 或完整地图也不能获得提示。设置「一般」为默认，按关持久的连续失败达到三次后显示；「多」立即显示，「无」关闭。重新进入或重启不清除失败次数，成功清零；手动停止、重置位置和编辑不计为失败。

每次提示先验证实际装配，只补下一步带完整参数的动作或控制结构，不整段覆盖玩家程序。相邻的 SVG 撤销按钮只能撤最新提示事务，后续手工编辑须保留；已有更晚编辑时不以旧快照强行还原。运行与暂停期间禁止插入或撤销提示。数据、状态和安全撤销边界见 [代码提示](CODE_HINTS.md)。


## 第十五关边界

第十五关显示为“第十五关 · 自动索敌”，`level_015`、order 15。原始 ProgramLevel 第十五关写两个模块，本次按用户明确确认采用三个；地图与战斗保留第十四关四格主路、左右支道、栅栏双向阻挡机器但放行攻击与雷达的真实几何。十波必须逐台击毁所有部件，敌方每模块 2.8 耐久，限时 240 秒，残骸约三秒淡出。仍为空装配、确认后编程及空 `main()`，不预装推荐模块或预填答案。

`allow_radar_events` 缺省 false，不能因雷达、变量或关卡编号隐式开启；事件另需雷达、变量和具名调用权限，以及实际可用雷达。顶层先声明全局 `variable`，再注册 `radar.onDetected { EnemyPosition -> target }`；禁止绑定常量、局部或后置名称，禁止把事件放进函数或控制块，禁止任意处理器代码。`EnemyPosition` 是固定载荷名，写入值与 `scan()` 同型；每 tick 更新该全局变量，无目标为 null。读取前判空，旧副本不自动刷新，同名局部不影响事件写入。暂停、停止与重试沿用同一会话和固定 tick 边界，前十四关的事件语法、补全和事件指令资料保持关闭。
