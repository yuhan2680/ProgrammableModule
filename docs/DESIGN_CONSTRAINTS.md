# 当前设计约定

本文件记录根据《可编程模块游戏设计》对话与当前需求采用的约定，更新于 2026-10-01。原有 `ProgramLevel.md`、`Mechanism.md` 保留作为历史设计参考；发生冲突时以用户最新要求为准。

## 本阶段

- 保留 Godot 底层、数据加载和地图编辑器，保留现有游戏流程，并提供使用相同底层能力的第一至第十六关，共 16 个教学关卡；第十关使用真实雷达追猎地图。
- 启动显示主菜单：开始、地图编辑器、设置、离开。地图编辑器可从主菜单创建，或从设置的玩家关卡文件列表打开现有地图。
- 主菜单的「开始游戏」与「地图编辑器」入口先用约 0.42 秒将白卡扩展到整个窗口客户区，圆角同时收尽，菜单文字、图标和按钮在铺满前渐隐；原字号与已有显示比例保持稳定，不截成图片拉伸。白卡铺满后构建并完成目标页布局，再用约 0.24 秒揭开目的页。鼠标与键盘共用入口，动画期间阻止重复点击；窗口尺寸变化、中途同步换页与系统关闭必须安全取消或继续到当前画幅，不执行迟到回调。设置入口仍沿用固定白卡的内容淡出淡入。
- 关卡选择固定每排七项，默认显示前七项教学关卡，展开后显示全部 16 个；更多关卡向下排列并纵向滚动，玩家关卡分类保留独立“+”导入入口。玩家栏独立支持展开/收起，折叠首排含导入卡与六张地图；总数只统计地图，搜索临时展示全部匹配项。
- 教学卡片只在实际通关后显示「✓ 已完成」，未通关隐藏名称下方说明；玩家署名与独立完成状态不受影响。
- 关卡页纵向滚动条固定在右侧既有留白中，仅内容溢出时可见，显示或隐藏不改变七列网格的横向位置及宽度。条使用透明轨道及浅灰蓝滑块，保留原生滚轮、拖动和键盘操作。
- 关卡列表靠近固定页头时透明渐隐，裁切区域延伸到页头下方原留白，首行位置和原滚动范围保持不变；指令集管理窗口的正文上下两端同样透明渐隐。仅合成滚动内容，不叠加白色、不模糊文字，导航、目录和滚动条保留独立显示；到达内容首尾时对应渐隐关闭，键盘焦点滚入清晰区域。
- 玩家关卡名称按卡片宽度先由 14 号缩小至最低 10 号，最多显示两行，仍溢出则以省略号结尾；原始地图名称与搜索不截断，悬停可查看全文。旧地图超长名称同样不能撑高整排。
- 每次进入关卡先显示独立组装页，初始装配为空；确认装配后才进入带行号的程序编辑页。
- 实时状态的敌人波次使用已击毁数量 / 总数表达，不再重复显示“第几波敌人来袭”。保留射击就绪、冷却及既有下一波等待倒计时；药丸随实际字号测量宽高。地图在普通和全尺寸预览中均避开顶部药丸与按钮，按剩余区域等比适配，状态显隐不改变预留空间或游戏数据。
- 玩家关卡问题统一显示在「设置 → 更多 → 玩家关卡列表」，包括损坏 JSON 和不可玩的草稿；开始游戏页移除旧问题入口。文件列表支持搜索、名称排序、原位重命名、单项删除、在地图编辑器修改和查看目录。四列表头滚到导航下方后吸顶，下方行可继续滚动；吸顶后仍可排序，隐藏行不穿透点击，键盘聚焦行须完整显示在表头下方。四列表头之间提供三个可拖动分隔线，表头和正文同步调整相邻列宽，保留最小宽度及省略号；当前会话内排序、筛选和刷新保留调整后的比例，吸顶后仍可拖动。正常黑字；普通异常 `#cb2222`；可能由更新版本创建与文件损坏用 `#e62020`，两种原因不得混淆。编辑后保持托管路径，退出返回文件列表；诊断不改变沙盒或战斗关卡的运行规则。
- 设置提供主音量、系统提示音音量、简体中文 / 繁體中文 / Español / English / 日本語、默认开启的 Tab 补全，以及代码提示「无 / 一般 / 多」（默认一般），修改立即应用并独立持久化。窗口分辨率同时保留原有 16:10 与常见宽屏选项，包含 1920×1080、2560×1440 和 3840×2160；各平台按当前显示器可用客户区启用选项，保持无黑边的画幅，旧偏好兼容。分辨率下方「缩放与布局」仅 Windows 可选；普通屏幕默认 100%，提供 110%/125%，物理屏幕至少 UHD（长边 3840、短边 2160）再提供 150%/200%。macOS 灰色禁用；其他平台同样禁用。百分比独立持久化且即时应用，Windows 手动缩放优先只改变文字字号，不按字体百分比拉伸卡片、图标、圆角、边距及画布；主菜单共享白卡及其菜单、导航、设置项、按钮和图标另随高分辨率 Windows 窗口等比扩大并保持居中，下拉弹层同步继承比例；小窗口与非 Windows 沿用原比例；控件只因文字最小尺寸需要而增大，窗口也只在实际布局放不下时扩大到可用尺寸，滚动正文不能强迫窗口一直长高。非 Windows 保留原画幅策略；不支持高档位时临时回退 100% 而不删除保存的偏好。
- 高分辨率卡片缩放后的文字须按实际显示比例生成清晰字形，不放大旧字形位图；手动 110%/125% 仍改变字号。分辨率、缩放、语言与代码提示列表采用打开时真实页面背景的毛玻璃，保留原生选择与滚动交互，纵向条使用透明轨道及低对比滑块。下拉列表用勾号标记已保存项，打开时以蓝色圆角底、白字白勾突出该项；鼠标或键盘移动时蓝底跟随原生焦点，确认前不改变已保存选项。
- 设置与「颜色与显示」复用主菜单白卡及背景，主菜单内容先淡出再淡入设置，转场不移动或淡出白卡。两页设置内容统一按原尺寸的 80% 显示，窄窗口避开导航文字；正文在白卡上下边缘整体透明渐隐，导航常驻卡片左上角并独立显示。纵向条降低对比度并保留闲置隐藏，键盘操作须滚入清晰区域。背景图库保持单排，横向滚动条略低于名称并降低对比度。
- 内置玩家内容包含移动、近战、射击、测距和雷达模块；玩家雷达在第十关开放，第十一关继承，该关敌人也有真实雷达模块。地块、限时闸门、可破坏障碍及敌人行为继续使用已注册定义。
- 未指定地块的位置，以及地图边界以外的位置，都是 void。任何机器的实体模块都不能进入或越过 void。
- 模块、地块、地图分别使用独立 JSON；地图仅引用稳定内容 ID。
- 地图属性的「管理关卡中允许使用的指令集」文字与圆形加号作为一组水平居中，位于模块限制下方；加号打开目录、搜索与指令开关窗口。开启允许使用，关闭限制使用。条目直接扫描现有指令 JSON 和模块注册表，每次打开刷新；新资料自动出现，但未被当前解释器支持的指令不能开启。模块限制仍独立控制实际装配。
- 可选 `properties.level.enabled_commands` 保存已有语法的稳定指令 ID 白名单；缺省字段仍只读取原独立 `allow_*` 开关，打开旧图不写入默认值。`main` 是必需入口；开启依赖指令同步启用必要前提，关闭前提同步关闭依赖项，合并为一次可撤销事务。正式游戏与未保存试玩均由解析器检查完整 AST，禁用的指令不能通过手动输入、未调用函数或嵌套表达式绕过；补全与阅读目录显示同一权限，不新增 DSL。
- 界面使用 Godot 控件与统一浅色圆角主题；替换显示不得改动底层规则。
- 数据定义、运行时实例、行为、世界模拟、编辑文档和显示层分离。
- 代码中的函数附中文用途注释；新功能优先使用明确的小类和普通控制流。
- 新增关键校验、状态切换和调度逻辑也附中文注释，便于后续程序员理解设计原因。
- `allow_random` 与变量、雷达、测距及函数权限独立；第十、十一关开启，旧关卡默认关闭。随机调用复用有限数值表达式入口，支持括号、一元正负号及加减；不增加新模块、乘除法、任意宿主方法或独立动作。正式运行由 GameSession 传入权限给 Parser，Runner 保持 AST 结构、类型与数值范围校验职责，不读取关卡权限。随机选取参数仍须接受原有动作范围、碰撞及能力校验。

## 第一关与玩家流程

- 第一关使用 S 形地板路径，出生位置 `(1.5, 7.5)`，终点 `(5.5, 1.5)`。
- 设计路线为向右 4、向上 3、向左 4、向上 3、向右 4 单位。路径中的未绘制区域仍是 void。
- 只解锁 `movement`，模块数量上限为 1。初始程序展示 `main()` 与少量示例，不填入完整答案。
- 不自动预装地图模板或上次草稿的模块。源程序可以自动恢复；玩家主动点击“载入上次装配”时才恢复已有布局。
- 在同一关卡内点击“编辑模块”返回组装时保留当前程序与装配，停止本次试运行；确认后返回编程，无需重新选关或重置模块。
- 组装页左侧「＋」玻璃目录展示全部已注册模块，介绍默认收起；不允许的类型禁用；满上限后不能新增，已有模块仍可按装配规则移动、命名和删除。
- 装配图自由缩放偏好默认关闭，独立持久化为布尔值。关闭时显示固定完整蓝图与白框，停用滚轮缩放、右键拖图和柔边；开启时恢复自由查看。开关仅控制视图，不改逻辑原点、相对偏移、出生点或草稿。
- 空装配首件可在图纸内任意落格，成功落点成为视觉装配原点；模型中第一个模块中心偏移仍严格为 `(0,0)`，后续模块使用相对偏移。只有一个模块时不能移离该原点，删空后允许重新选点。视觉原点不写入关卡出生坐标或草稿。
- 后续新增或移动必须与任意已有模块的实际矩形边缘共边，接触长度大于零。允许分支，不要求串成单链；角点接触或空隙不算连接。
- 删除中心或桥接模块可以留下不完整草稿。`validate_editing()` 只检查结构、网格、类型、数量、命名与重叠，允许空装配、缺中心和断连，便于保存及手动恢复后继续修复。
- 最终 `validate()` 要求非空、存在中心偏移为 `(0,0)` 的模块，且全部模块沿边连通；`build_document()` 还要校验完整出生占地。缺中心、断连或占地进入 void 时禁用确认按钮，悬停展示原因。直接调用也不能绕过最终校验。
- 玩家修改程序和装配后运行；每次重新运行使用出生状态，不累计上次失败的位置。
- 抵达或经过终点半径范围视为通关。程序结束但未到终点、移动被 void 阻挡，均给出失败原因并允许继续编辑。
- 暂停冻结程序与世界逻辑 tick；恢复继续执行；「重置位置」保留玩家源程序和装配草稿。「重置代码」显式恢复当前关卡的 starter_program 并停止旧运行，保留装配和通关记录，支持撤销；正常关卡更新草稿，编辑器试玩继续保持会话隔离。
- 游戏装配使用 `0.5` 格偏移网格，范围 `-4..4`。模块实例名遵循英文字母或下划线开头、后续字母数字下划线的标识符格式。
- 关卡定义保存在地图 `properties.level`。玩家关卡统一从平台玩家目录读取（macOS 文稿与 Windows 用户根中的 `ProgrammableModule/saves`，其他平台仍为 `user://levels`），旧关卡按列表单条迁移复制原始 JSON，全部完成后清理旧副本并退役；首次有旧关卡时仅询问一次，明确放弃才删除未迁移关卡，包括地图编辑器普通「保存」产生的托管地图和原有导入地图；选关分类显示「玩家关卡」，「导入关卡」保留为导入动作。程序、装配草稿与通关记录存入 `user://solutions`；两者不互相覆盖。玩家地图绝对路径仅由 `PlayerLevelPaths` 授权，不扩大通用资源路径权限，详见 PLAYER_SAVE_LOCATION.md。
- 导入关卡直接使用 macOS / Windows 原生 JSON 文件选择器，默认下载目录；验证后自动写入独立玩家副本，冲突自动去重并刷新列表。来源文件始终只读，取消不创建目录，不显示手动复制提示；换页后的迟到选择回调无效。

- 地图 `player_spawn.modules` 继续作为底层格式与缺省关卡规则的来源保留；正常关卡和地图编辑器测试都不会自动安装该模板，不需要删除它或改变既有 Schema。
- 主音量和系统提示音音量、语言、Tab 补全和代码提示档位写入 `user://settings.json`，与关卡、程序草稿、通关记录分开保存。
- 无关卡目标的普通编辑器地图可以作为沙盒导入；没有出生点的编辑草稿还不能进入游戏。

## 地图编辑器保存与测试

- 地图区域不绘制白色卡片与阴影，以原卡片外框范围作为可视和编辑边界，不再保留卡片内边距。顶部工具栏使用「缩小 / 放大 / 指引」和「新建 / 保存 / 撤销 / 重做 / 更多」两个药丸组，组内细线分隔，重载保持独立；缩放使用右侧并列 − / + 的放大镜图标，新建继续使用普通加号。页头与更多菜单按输入方式显示焦点：鼠标操作隐藏蓝色焦点描边，键盘操作显示，保留实际焦点与菜单关闭后的导航顺序。放大或平移后，地图的地形、纹理、实体和选择预览须整体透明渐隐，边缘不叠白色或模糊；工具栏和滚动条不参与地图边缘渐隐。地图的横、纵原生滚动条使用低对比度蓝灰色，活动时显示、拖动按住时保持显示，停止后共用侧边栏的空闲淡出；只改透明度，保留原占位、点击区域和地图画幅。可视区域外不能绘制，视图变化不修改地图、保存状态或撤销历史。属性白卡的滚动正文在上下边界整体透明渐隐，不模糊或叠白层；到达首尾时相应渐隐关闭，键盘焦点须滚入清晰区域。保留原表单尺寸、留白和滚动条独立显隐。

- 地图属性中的输入框、数值框和按钮在点击卡片或页面空白处时真正取消焦点，而非只隐藏描边；光标停止显示，合法输入按原提交规则保存，无效数字恢复有效值。点击输入内部或键盘导航正常保留、转移焦点。浮层和模态窗口不能将点击透传给背景表单或地图。

- 新建地图在创建时分配 `map_` 加十位独立随机数字的 ID，每位允许 `0..9`，可重复且可前导零。读取内置地图、教学关卡及玩家 JSON 的真实 ID，并避开本进程已分配的未保存 ID；有界重试失败保留当前文档、路径、历史和视点，不创建地图文件。ID 是只读显示，可选择复制但不能键入、删除或粘贴修改，十四字符按真实字号预留完整宽度。名称等属性提交始终取模型 ID，不采信显示字段；打开旧地图保持原 ID，不迁移旧格式。
- 「创作者」位于名称与 ID 下方，保存到可选 `properties.level.creator`，新编辑的名称最多 30 字符、署名最多 11 字符，沿用原草稿空名称与空署名行为；旧格式仍兼容最多 128 字符署名，旧图缺失字段默认空。未修改的旧长名称与署名可原样保留，不能在表单回填时截断。名字保留中文、emoji、内部空格与大小写，编辑提交仅去掉首尾空白；空值不生成额外元数据。玩家关卡卡片署名按当前语言格式化，姓名不参与翻译，未署名仅显示「玩家关卡」。完成状态单独保留。
- 「副标题」独占名称与 ID 和创作者之间的一排，输入光标正常闪烁，最多 70 个 Unicode 字符；键入和粘贴先过滤 emoji、控制码及不可见格式字符，再限长，保留文字、数字、空格和常用标点。保存到可选 `properties.level.subtitle`，读取与写盘使用同一校验；清空移除字段、旧图缺省不产生修改。编程页标题下优先显示副标题原文，切换语言不翻译；留空恢复默认目标说明，不替换描述、指引或真实通关条件。名称、署名、副标题在回车、失焦、保存及试玩前以同一事务提交，ID 保持不变。
- 右键玩家关卡提供「重命名关卡」「打开关卡所在文件夹」以及红色「删除关卡」。重命名在卡片原名处全选并编辑，不创建弹窗或绘制外层蓝框，保留文字选区及闪烁光标；Enter 保存、Esc 或移开焦点取消，不自动提交。原生中文输入法确认不等于保存。新名称为 1 到 30 字符，仅接受 Unicode 文字、十进制数字及 ASCII 下划线/连字符，不裁剪首尾空白、不静默过滤非法粘贴；UI 和落盘接口均校验。非法输入原位标红并说明原因，旧名称不因新增规则而无法载入。重命名仅更新显示名，ID、路径、元数据和游玩记录不变；写盘前重新核对文件快照，失败不覆盖原件。打开目录只作用于当前目录中的玩家地图，使用系统文件管理器。只删除当前列表指向的游戏内地图文件；教学与加号入口没有删除菜单，外部导出原件、其他地图与游玩记录不受影响。当前文件与目录快照不一致时拒绝删除并提示刷新；取消、换页或刷新使旧菜单目标失效。

- 普通「保存」直接写入平台玩家目录，文件名自动分配；macOS 沙盒首次通过原生目录选择器取得文稿访问权；新建地图各自分配文件。打开已有托管地图后原位更新；打开外部或内置地图后生成玩家副本，普通保存不能覆盖来源原件。
- 「另存为」保留任意位置导出 JSON；已存在的托管绑定与导出路径分别保存，导出后再次普通保存仍更新同一托管副本。新建或打开另一张地图时重新确定绑定，试玩返回继续保留绑定。
- 保存前按内置关卡及其他玩家 JSON 的真实 ID 去重。新建地图保持创建时 ID；若创建后被另一个文件抢占同 ID，保存明确失败，不能偷偷改号。导入或打开来源生成副本时，十位格式 ID 的真实冲突重新随机分配同格式，其他旧 ID 沿用有限后缀。绑定更新排除自身文件；文件名冲突可只给文件名加后缀，不影响新建 ID。新文件不能覆盖既有同名文件。托管路径必须位于安全的 user:// 子目录，拒绝上级路径和符号链接。
- 沿用 `MapCodec.save_file(..., false)` 的同目录临时文件与原子替换，允许无出生点等未完成编辑草稿。只有写盘成功才提交新 ID、路径与保存点；失败保留输入文档、原文件及历史。未知字段和格子扩展完整往返；草稿仍须满足正式关卡校验后才可在选关页游玩。

- 分类折叠只影响可见性，不改变地图、输入值和撤销历史，试玩返回保留折叠状态。「场景编辑」包含尺寸和地形工具；「场景玩法与行为控制」包含起终点、限时和两项玩家上限；「敌人攻击方式与行为控制」为同级独立折叠分类。折叠敌人时关闭模块选择浮层并取消未落地预览，不删除配置。
- 编辑器时限默认60秒，必须大于0且不超过3600秒，以0.1秒精度转换为既有 `max_ticks`。保存/测试前提交有效限时，空白与0不能作为不限时；编辑文档事务保留其他规则和扩展数据。
- 编辑器限时模式显式写入 `completion_mode: "reach_or_clear"`，到达坐标终点或清除全部已注册敌人即可通关。初始无敌人不能立即获胜，尚未出现的波次不能忽略。没有终点和敌人也可测试，但仍按截止时间失败。
- 世界失败先结算，截止tick真实达标允许通关；主程序结束不能停止计时。倒计时仅用模拟tick，暂停冻结、重试恢复。未启用新模式的既有教学和导入地图保持原目标与时间语义。

- 「场景玩法与行为控制」独立放置起点与可选终点，地形下拉不包含出生点。起终点用单击放置，不走拖动或框选批量逻辑；两个红字重置按钮只移除对应内容，支持保存与撤销重做。
- 终点不必添加：无目标地图仍可保存与自由测试；已有战斗目标不能被“重置终点”误删。添加终点复用 `properties.level.goal`，不另建一套通关机制。
- 场景宽高输入限制 `1..64` 整数，键入、粘贴和应用均校验。通用地图格式仍兼容 `1..256`，读取旧大地图不可静默裁剪；模块数量上限不受此输入规则影响。

- 敌人开关保存为 `properties.level.enemies_enabled`；显式关闭保留敌人数组与模板，只阻止运行时生成敌人。旧地图缺省维持原运行行为，打开编辑器不能隐式改写开关或产生历史。
- 敌人模板保存在 `properties.editor.enemy_template`，包含 `module_limit`（1..256 的整数）、`module_health`（0.01..1000000 的有限数字）和非空 `module_ids` 顺序列表；数量不能超过模板上限，模块必须已注册。修改模板不回写已放置敌人的装配或耐久，共享模块定义及玩家耐久不受影响。
- 敌人组合操作分两排：添加与删除圆形按钮在上排居中，模块选配独占下排的可用宽度；每排四个药丸，更多槽位继续换行，字体随全局字号设置重新排版，不撑宽固定属性卡片。
- 敌人组合按真实模块宽度横向共边排列，首件偏移为零；地图落点吸附半格，完整模块占地须在地图内的可通行地板上，且不与玩家出生模块、现有敌人或场景对象重叠。加号进入半透明 SVG 预览，左键按下只提交一组；右键或 Esc 取消，缩放、滚动、失焦、隐藏或切换工具清除旧预览。预览不能写入历史；开关、模板和成功放置均通过编辑事务保存、撤销与重做，失败不改地图。
- 敌人组合加号旁的圆形删除按钮先进入敌人框选模式；沿用矩形手势，松手只保留选区及整组高亮，再次点击垃圾桶批量删除。区域与任一真实模块正面积相交即选中整组，贴边和组合空隙不算；不修改地形、机关、玩家或敌人模板。删除为一次可撤销事务；右键、Esc、切换工具、折叠或关闭敌人以及点击卡片空白处取消选择和工具高亮，空白点击也真正释放按钮焦点。
- 框选完成后，鼠标移出地图并移向垃圾桶不清除已提交的敌人选区；普通画笔越界结束笔画及尚在拖动的矩形捕获规则仍按原路径处理。
- 新放置敌人只引用已注册的 `auto_chase_attack` 行为，由可信固定 tick 控制器根据真实存活模块提交移动、近战或射击动作；不从 JSON 执行任意代码，不凭空赋予移动或武器能力。地形、碰撞、射程、冷却和部件损伤继续使用现有模拟规则。

- 编辑器的「开始测试」复用正常游戏的空装配 → 确认装配 → 编程流程，不提供直接执行单次 `move` 的表单。
- 测试采用当前未保存地图的独立快照，以及编辑器当前的内容注册表，无需先保存或重新从磁盘读取地图。
- 模块数量上限由编辑器设置为 `1..256`，写入 `properties.level.module_limit`，与其他地图修改一起保存、撤销和重做；每次测试使用当前值。
- 玩家耐久按现有每模块损伤机制工作，显式 `properties.level.player_max_health` 覆盖实际玩家装配中各模块的初始/最大耐久，支持正小数，最大1000000000；不能修改共享定义或敌人。旧地图缺省继承模块定义，新建地图默认1。输入、地图格式、关卡与运行时均拒绝非法值，保存、撤销和试玩遵守同一文档事务。
- 「校验」检查地图和关卡定义。玩家真实装配的中心、连通和完整出生占地在确认装配时检查，不用出生模板的占地提前阻止进入组装页。
- 每次开始测试建立新的空装配会话。同一次测试内切换组装/编程、停止或重置位置会保留当前程序和装配；返回地图编辑器即结束本次测试，下次不会恢复上次测试作品。
- 返回时保留同一个编辑器文档、文件路径、未保存标记和撤销/重做历史，不通过重新打开文件恢复页面。
- 测试期间不读取或写入正式 `user://solutions` 草稿和通关记录，即使地图 ID 相同也不互相影响。界面隐藏保存草稿和载入上次装配；自动保存和完成事件不落盘。
- 独立运行 `scenes/map_editor.tscn` 同样由 `GameShell` 包装编辑器；编辑器只发出测试请求，执行与计时复用 `GameWorkbench` / `GameSession`。
- 普通关卡保持原有草稿与进度行为，内置第一至第十六关。`data/maps` 与 `data/levels` 本轮不迁移或合并。

## 已采用的模拟规则

- 世界每秒 10 个逻辑 tick，动作先计算再统一提交。
- 模块默认大小为 0.5 × 0.5 格；模块中心偏移决定真实占地，不允许实体模块彼此重叠。
- 多个移动模块的有效速度相加。JSON 的 `move_speed` 单位为格/秒。
- `move(角度, 距离)` 使用绝对方向：0° 右、90° 上、180° 左、270° 下。
- 地图坐标 x 向右、y 向下，以格为单位，支持连续位置。
- 移动是有限距离动作，遇到不通行地形后停在接触点并报告 `BLOCKED`。
- 当前没有惯性、机身旋转、滑墙或机器之间碰撞。近战按真实射线向可破坏对象与敌我模块结算伤害，敌人只执行已经注册的固定行为。
- 中心与沿边连通约束属于玩家游戏装配层；底层地图格式和 `MachineFactory` 不增加通用拓扑限制。碰撞仍取实际模块矩形的并集，不把空隙填成实体，也不引入额外 Core。

## 后续方向与边界

游戏计划包含战斗模式、设计模式、对战模式。模块决定可调用能力，程序决定行动。不添加统一 Core 模块，也不引入已取消的能源、维修系统。

当前 DSL 已实现单一 `main()` 入口、逐行 `move(角度, 距离)` 与第三关解锁的 `attack(角度)`、数值字面量、空行和 `//` 注释。执行器通过 `SimulationWorld.request_move()` 和命令完成状态顺序等待，不执行任意 GDScript。相邻调用强制换行，不接受分号；错误包含行号。

完整语言仍在后续阶段实现。玩家入口保持 `main()`，不是 `init()` / `tick()`；当前无限循环使用 `loop {}` 并按关卡开放。Lexer、Parser、类 Kotlin 的显式 AST 节点和解释器保持分离。`simultaneously {}` 需要独立的 AST 与调度语义，不应伪装成普通函数调用。上述为早期语言规划；当前已逐关开放循环、条件、有限数值表达式、自定义无参函数、命名模块调用及并发块。第十一关显式开放常量、变量与赋值；绑定可保存数值、雷达快照、坐标或 null，数值动作仍严格要求有限数字；函数参数与返回值尚未开放。当前边界见 [函数复用](FUNCTIONS.md) 与 [常量与变量](VARIABLES.md)。

原始雷达规划中的 `radar.Detected`、`scanAll()` 与 `Target.type` 仍属后续范围，不恢复 `scanAllInfo()`。按用户最新要求，第十、十一关已开放 `scan()` / `模块名.scan()` 及目标 `Angle()`、`Position`、`Distance`；完整规则见 [玩家雷达](PLAYER_RADAR.md)。雷达范围与地块的 `radar_block` 为数据配置，扫描只返回最近可见敌机的当次快照，无目标为 null；玩家查询与敌方锁定共用范围和遮挡语义。

抓取模块未来遵循 `grabber.grab(角度)`、1.5 格范围与 `grabber.Holding` 的设计。上述系统现在只作为扩展约束，不提前实现。

## 第四关扩展

当前内置四关。`LevelDefinition` 新增 `allow_tick`（默认 false）、`max_ticks`（默认 0，不限时）和 `destroy_enemy` 目标；射击调用按允许的模块行为解锁。第四关上限 1、敌人初始位于右侧 6 格，向左移动 4.5 格后近战攻击。

`GameSession` 在战斗主程序结束后继续推进世界；玩家死亡优先于同 tick 敌人全毁的胜利，超时失败，暂停/重试语义不变。`MapCanvas` 只显示敌方模块耐久和子弹；`LevelThumbnail` 从地图敌人数据生成选关 SVG。

## 第五关扩展

`allow_named_calls` 默认 false；第五关显式开启。Lexer 保留小数词法，Parser 使用显式 `CallNode.receiver`，Runner 在提交任何动作前检查所有实例名与能力。世界接口可选 `module_id`，空值保持广播，非空精确筛选能力来源；命名不改变真实模块占地或各实例冷却。

`alarm_guard` 等待警报，`prison_alarm` 在同 tick 全部伤害提交后检查绑定警卫；警卫仍活则立即处决全部玩家模块。`security_gate` 仅在引用的全部已注册敌人和可破坏对象被清除后解锁。`escape_prison` 还要求玩家沿实际路径到达出口；失败先于胜利。

UI 从世界读取 `triggered` / `unlocked` 状态，SVG 和地图缩略图只呈现，不自行控制规则。新增字段兼容 `format_version: 1`；坏引用拒绝，未知扩展仍保留。前四关 JSON、草稿数据及编辑器测试隔离约定不变。


## 第六关扩展

`properties.level.allow_loops` 可选且默认 false，第六关显式开启，前五关 JSON 保持不变。Parser 使用显式 LoopNode，Runner 使用有界执行帧维护 main 的循环位置，不展开源码、不按关卡编号硬编码十次。每个 step 仍只推进至多一个模拟 tick；循环边界本身不消耗世界时间。

循环仅能出现在 main 中，tick 回调仍为有限的 attack/shoot 短动作。整树预检、层级/节点数量限制和空块拒绝避免语法树或结构遍历卡死；零距离移动也保持每次一个 tick。到达目标后由 GameSession 取消解释器，暂停/重试和草稿隔离约定延续。

33×23 阶梯地图采用现有 floor SVG、位置目标与一模块装配，不增加新的模拟对象类型。观察区允许缩小至每格8像素以完整显示本关；小网格的机器人圆环只属于显示，不改变真实占地。详见 [循环与阶梯](LOOPS_AND_STAIRCASE.md)。

## 自定义关卡引导与文件入口

- 地图属性在创作者右侧提供「关卡引导 ＋」。分页编辑复用顶层 `dialogue`，新建或修改的页面标记 `format: "markdown"`；缺省或 `plain` 保持旧地图与教学兼容。
