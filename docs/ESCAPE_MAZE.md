# 第十六关：逃脱

本关为既有指令的迷宫逃脱练习，正式 ID 为 `level_016`，order 为 16，标题为“第十六关 · 逃脱”。英文为“Level 16 · Escape”，繁體中文为“第十六關 · 逃脫”。

## 关卡与地图

- 数据位于 `data/levels/level_016.json`，固定尺寸 27×17；沿用地图格式版本 1。
- 207 格 `floor` 和 252 格 `wall` 覆盖全图，外圈封闭。通路是带岔路、死路的单格迷宫，没有运行时随机生成。
- 起点锚点 `(1.25,1.5)` 位于左上角地板 `(1,1)`；终点 `(25.25,15.5)` 位于右下角地板 `(25,15)`，`reach_position` 半径为 0.25。
- 最多安装两个模块，没有敌人或对象，`max_ticks: 0` 表示不限制时间。到达目标后沿用正常通关流程。
- 继承第十五关的五种允许模块与全部独立解锁标志。不新增 DSL，也不修改前十五关的数据、权限或目标。

所有地板连通，通路图无环并含 13 个死端。起点到终点最短路径为 114 个一格步；从向右的初始方向遵循右手沿墙规则，路线为 170 个一格步。这些是地图布局指标，不是运行时绕过碰撞的通关条件。

## 推荐装配与探路

先安装测距模块 `sensor` 作为原点 `(0,0)`，右侧偏移 `(0.5,0)` 安装移动模块 `drive`。两个半格模块合计占地 1×0.5 格，出生时横向覆盖 `[1,2]`、纵向覆盖 `[1.25,1.75]`。改变行进方向不会旋转机器；整机按照真实矩形并集接受碰撞与路径检查。

采用此装配并保持一格步长时，先检查 `sensor.distance(方向) > 1` 再前进一格，可以区分相邻地板和墙壁。读数起于测距模块中心，并不等于任意装配都能直接使用的移动距离。修改装配或步长后必须重新考虑占地，不能通过缩小碰撞箱或更改共享测距规则保证通过。

玩家可用 variable 保存方向，用 if 选择右侧、前方、左侧或掉头，再将测距和一格移动放入 loop。沿固定一侧墙探索能够处理岔路与死路。实现复用已解锁的有限加减、比较、条件、循环和具名模块调用；不要求随机函数、雷达事件或新语法。

## 窄通道中的移动精度

本关暴露了连续累加单精度 Vector2 位移造成的位置漂移：一格宽的合法装配在长路径转角会被误判进入侧墙。MovementCommand 记录动作起点；SimulationWorld 每 tick 根据起点与累计标量行程重建目标，对当前位置到目标的实际位移进行原有完整扫掠，再提交已验证位置。普通移动与 simultaneously 中的移动保持一致。未增大碰撞容差、缩小占地或将玩家位置吸附到网格；非整数距离、动态障碍与高速扫掠沿用原有规则。

## 流程与提示

每次进入仍从空装配开始，玩家确认后进入编程，初始源码只有空 `main()`。`player_spawn.modules` 仅是合法地图模板，不自动装入玩家会话；参考探路程序不预填到编辑器。暂停冻结模拟，重试恢复位置并保留本次装配和代码，草稿与通关记录遵守现有教学流程。

代码提示使用正式教学来源与完整地图快照核对，并用实际装配在独立会话中验证参考方案。提示不得改变玩家会话或解锁旧关卡，不适用于导入副本或编辑器测试。

## 验证范围

`tests/escape_ui_runner.gd` 覆盖三语关卡搜索与完整说明、真实装配确认、地图出口可见性、增量提示及改名模块绑定；独立提示会话不会写入玩家通关记录。`tests/headless_runner.gd` 的窄通道用例覆盖长动作、逐格转弯与非网格终点。

`tests/escape_level_runner.gd` 用于检查地图尺寸、连通与分支、两模块限制、继承权限、空装配、实际 DSL 测距探路、真实碰撞及暂停重试。应通过真实 GameSession 完整运行并验证到达终点，不能以静态寻路结果代替模拟通关。关卡列表、缩略图、提示和本土化还应纳入现有回归；具体执行结果以测试日志为准。
