# 第八关：同时执行与联动警报

依据 [ProgramLevel.md](https://github.com/yuhan2680/ProgrammableModule/blob/main/ProgramLevel.md) 第八关：上限三个模块，两个警报器分别在出生点左侧两格、右侧三格，先同时解除警报，再向上逃离。任一警报被单独摧毁会触发另一个；全部解除前禁止移动。本关通过 `simultaneously {}` 教学多个动作在同一逻辑 tick 启动，不通过匹配玩家源代码判定答案。

## 地图与装配

`data/levels/level_008.json` 延用 `format_version: 1`，地图大小为12×10。出生中心 `(5.5,7.5)`，左警报 `(3.5,7.5)`，右警报 `(8.5,7.5)`，出口中心 `(5.5,1.5)`、半径0.25。起点房间地板为 `x=2..9,y=6..8`；上方走廊为 `x=5..6,y=1..6`，其余位置仍是 void。出口并排设置两扇尺寸1的安全门，中心分别为 `(5.5,4.5)` 和 `(6.5,4.5)`，共同封住两格宽走廊。两扇门均引用两只警报作为解锁条件，一起解锁；门锁贴图保持正常尺寸。

每次进入仍先空装配；地图内的出生模板仅供数据格式与维护验证，不自动安装模块。保留已开放的移动、近战、射击模块，数量上限为3。教学建议从中心向右连接三个半格模块：

| 实例名 | 类型 | 相对中心偏移 |
| --- | --- | --- |
| `left` | 近战 | `(0,0)` |
| `drive` | 移动 | `(0.5,0)` |
| `right` | 近战 | `(1,0)` |

机器中心只要求存在模块，不要求必须是移动模块。两个警报尺寸各为0.5格，因此 `left` 的中心到左警报右表面、`right` 的中心到右警报左表面均为1.75格，在现有2格近战射程内。此布局沿用半格网格、共边连通与真实模块占地，没有扩大射程或添加关卡特例。如果把驱动放在中心、两边直接各接一个近战模块，右侧目标仍在射程外；教程明确要求通过装配位置解决距离差。

初始程序仅包含空 `main()`，不预填同时攻击或移动答案。以下为维护者复验程序，不会加载到玩家编辑器：

```text
main() {
    simultaneously {
        left.attack(180)
        right.attack(0)
    }
    move(90, 6)
}
```

成功条件同时要求两个警报已解除、玩家存活，并沿合法路径到达出口。仅解除警报但没有离开，不算完成。前七关 JSON、草稿及通关记录保持原样。

## 同时执行语义

关卡元数据 `allow_simultaneous` 为可选布尔字段，缺省为false。第八关显式开启；原有 `allow_tick`、`allow_named_calls`、`allow_loops`、`allow_conditionals` 仍各自控制原有能力。新增关键字不改变旧程序的顺序执行方式。

`simultaneously {}` 是独立的控制结构，由词法分析、语法分析、显式 AST 和执行器处理，不能伪装成普通函数或执行任意脚本。块内至少需要两条直接的 `move`、`attack` 或 `shoot`，支持已开放的具名调用。块内不嵌套循环、条件或并发块；并发块不能放进 `tick()` 回调。它可以作为 main 流程中的语句，块后代码等待全部动作结束，再顺序执行。

在提交首个动作之前，预检整个块的模块名称、能力和资源占用；同一模块不能被两个并发动作占用，整台机器最多同时执行一个移动命令。无名称调用会占用其选择的所有同类模块，不能与同模块的具名调用重叠。移动仍驱动整台机器，使用原有完整路径碰撞；同时执行不允许穿过 void、机关或其他不可通行对象。

所有子动作从同一个世界 tick 开始。近战在该 tick 提交命中；射击动作结束只代表完成发射，不代表弹丸已经命中；移动则等待其有限距离完成。弹丸仍按真实速度与距离飞行，因此“同时发射”不保证“同时命中”。同时解除本关两个警报的判据是伤害在同一 tick 完整结算，不是指令名称或源码文本。

## 警报和目标配置

新增注册对象类型 `paired_alarm`，每个对象包含稳定 `id`、世界 `position`、标量 `size` 和 `properties`：

```json
{
  "id": "alarm_left",
  "type": "paired_alarm",
  "position": {"x": 3.5, "y": 7.5},
  "size": 0.5,
  "properties": {"max_health": 1, "partner_id": "alarm_right"}
}
```

配对必须指向另一个有效联动警报，并相互引用；非法引用应在创建世界前报告，不把任意扩展字段当成代码执行。静态 JSON 与运行时耐久、触发、门解锁状态分离。安全门继续使用现有 `security_gate` 和 `required_object_ids`，不增加独立的门行为。

目标 `escape_alarms` 保存两个 `alarm_ids`、出口 `position` 及 `radius`。目标引用真实对象，不能借助未知 ID 绕过关卡要求。未解除全部目标警报前的实际移动会失败；单独解除一个警报也失败。同 tick 的全部伤害应先统一提交，然后检查剩余警报及解锁条件，避免按调用顺序错误触发已经同步解除的警报。

失败保留玩家代码和装配。暂停冻结世界与正在等待的并发动作；停止、重置位置和再次运行沿用既有取消/新世界机制，恢复警报与门的初始状态。正常关卡结果使用既有草稿存储；编辑器试玩不读取或覆盖正式进度。

## 教学、显示与验证

教程解释左右距离差、中心可放近战模块、具名方向、同时执行的等待边界以及解除后向上离开。中英文译文通过 `GameI18n` 提供，模块名与玩家源代码不自动翻译。指令集合自动扫描新增的 `data/commands/100_simultaneously.json`，按 `allow_simultaneous` 显示解锁状态；内容说明包含“同时”“动作”等搜索文本。

地图与缩略图展示联动警报及安全门；工作台目标、指引、状态药丸与全尺寸结果反馈读取会话状态，不参与规则计算。回归需要覆盖：参考装配与解法、两种顺序攻击失败、提前移动失败、同 tick 同时命中成功、资源冲突与未解锁语法、等待最长动作、暂停/重试与前七关兼容。完整验证入口为 `tools/test.ps1` / `tools/test.py`，实测结果由本轮验证记录说明。
